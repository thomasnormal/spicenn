\begin{abstract}
This note summarizes the circuit-level neural-network architectures that have
worked so far in the SPICENN experiments.  The long-term target is a trainable,
mostly combinatorial neural network whose forward pass, backward signal
propagation, and weight writes run inside SPICE using transistor, resistor, and
capacitor primitives.  Python is allowed to provide sample rails, target rails,
and coarse guiding waveforms, but not to compute hidden activations or
gradients.  The current evidence splits into two tracks: a chip-faithful
device-level direct-flow track that now solves XOR with per-synapse stored
pre-activation traces, an emerging tiny-MNIST direct-flow bridge, and a
higher-accuracy MNIST local-feature phase-training track that has crossed
90\% but still uses a more structured local-feature rule and is not yet the
final pure direct-flow dense architecture.
\end{abstract}

\section{Goal And Current Status}

The desired hardware contract is:
\begin{enumerate}
  \item Python drives external inputs, target rails, and phase/guide waveforms.
  \item The circuit performs the forward pass by charging pre-activation and
    activation capacitors.
  \item A backward window opens after the output comparison.
  \item Output error current propagates backward through capacitor-held readout
    weights and hidden activation gates.
  \item Weight capacitors are updated by local transistor stacks gated by
    backward error and saved pre-activation traces.
\end{enumerate}

Equivalently, Python is the experiment controller, not the neural arithmetic
engine.  It may choose the next sample, set the target rails, and open or close
guide windows.  It must not compute hidden activations, sample hidden
pre-activations, compute hidden deltas, or calculate weight updates.  In the
direct-flow decks those quantities are voltages produced by ngspice transient
simulation and stored on circuit capacitors.

Table~\ref{tab:status} gives the shortest honest summary of where the work is.
The direct-flow XOR result is the closest to the target architecture.  The
local-feature MNIST result is the strongest accuracy result, but it is a
structured local feature architecture with a phase-portable update rule rather
than the final dense direct-flow synapse design.

\section{Preliminaries}

For readers coming from the machine-learning side, the analog primitives used
throughout this note are listed below.  Each row shows the standard schematic
symbol next to the text definition so the two stay together on the page.

\textbf{Capacitor ($C$).} Stores charge $Q = CV$, so the voltage across a

\\

&
\textbf{Resistor ($R$).} Sets a current $I=V/R$ and, when paired with a
capacitor, gives a leakage time constant $\tau=RC$.  Used here as a slow
discharge path on stored voltages, e.g.\ $R_{\mathrm{leak}}$ on

\\

\textbf{NMOS transistor.} A voltage-controlled switch: when the gate voltage

\\

\textbf{Source follower.} An NMOS biased so that the source voltage tracks

\\

\textbf{Signed differential pair.} A signed quantity $x$ is encoded as

\\

\section{Datasets}

The experiments in this note use three benchmarks of increasing difficulty.

\begin{description}
  \item[XOR.] The 4-sample 2-input boolean XOR function.  Smallest task that
    is not linearly separable, so any working result is evidence that a real
    hidden layer is being trained.  Used as the canonical proof-of-concept for
    the direct-flow architecture.
  \item[Tiny MNIST (\code{mnist01\_N}).] A balanced binary subset of MNIST
    restricted to digit classes 0 and 1, with $N$ training samples.  Earlier
    runs tried several fixed sensory front ends, but the current circuit
    architecture work is pinned to \code{mnist01fixed8\_64}: one reasonable
    fixed Haar/pool feature option, held constant while the synapse, neuron,
    backward-flow, and write blocks are improved.  The goal of this benchmark
    is to isolate whether the readout and hidden-write dynamics can converge,
    not to keep optimizing preprocessing.  Test accuracy is reported on the
    held-out MNIST-0-vs-1 split.
  \item[Small multiclass MNIST (\code{mnistKfixed8\_N}).] A balanced
    \(K\)-class subset using digit classes \(0,\ldots,K-1\), e.g.\
    \code{mnist3fixed8\_30} for ten samples each from classes 0, 1, and 2.
    This benchmark is now used as the gate before full 10-class MNIST: it
    exercises the multi-row output/error/write code without changing the fixed
    input frontend.
  \item[MNIST.] The standard 10-class handwritten-digit dataset (60k training
    / 10k test, $28{\times}28$ grayscale).  Used for the local-feature
    phase-training track; the headline number is test accuracy on the full
    10k test set.
\end{description}

\section{Simulation Cost Controls}

The current SPICE decks are slow for two separate reasons: the transient
window is long, and the measurement harness asks for many voltages at many
cycle offsets.  The generator now exposes two explicit simulator knobs:
\code{--tran-step-ps} and \code{--spice-accuracy-preset}, and two cycle-shape
screening knobs: \code{--cycle-ns} and \code{--skip-train-refire}.  The default
remains the historical setting,
\[
  \code{.tran 10p Tstop uic},
  \qquad
  \code{method=gear maxord=2 rshunt=1e12 gmin=1e-12}.
\]
This is deliberate: the write dynamics are currently sensitive to integration
granularity.  On a 20-sample \code{mnist01fixed8} readout-only calibration, the
10 ps standard run reached 90\% final accuracy in about 42 s.  Relaxing the
tolerance preset at 10 ps preserved the 90\% result but gave essentially no
speedup.  Coarsening the transient step did speed up the deck, but changed the
learning outcome:
\[
\begin{array}{ccl}
10\mathrm{ps}\ \mathrm{standard} &:& 90\%,\ 42.3\mathrm{s},\\
10\mathrm{ps}\ \mathrm{fast} &:& 90\%,\ 41.2\mathrm{s},\\
7.5\mathrm{ps}\ \mathrm{standard} &:& 90\%,\ 53.6\mathrm{s},\\
5\mathrm{ps}\ \mathrm{standard} &:& 95\%,\ 78.0\mathrm{s},\\
12.5\mathrm{ps}\ \mathrm{standard} &:& 50\%,\ 38.1\mathrm{s},\\
15\mathrm{ps}\ \mathrm{standard} &:& 50\%,\ 29.7\mathrm{s},\\
20\mathrm{ps}\ \mathrm{standard} &:& 55\%,\ 23.9\mathrm{s},\\
25\mathrm{ps}\ \mathrm{standard} &:& 50\%,\ 20.0\mathrm{s}.
\end{array}
\]
So timestep choice is not a harmless runtime flag for the current circuits; it
is a circuit experiment because it changes the effective charge delivered by
narrow switching/write events.  Coarser steps can destroy the learning
trajectory, while a finer 5 ps run improved this calibration from 90\% to
95\%.  The safer speed policy for screening is therefore:
\begin{enumerate}
  \item use \code{--measure-detail light};
  \item use one readout offset, usually \code{--readout-sample-offsets-ns 2.95};
  \item disable \code{--eval-each-epoch} unless the run is specifically looking
    for transient optima;
  \item use smaller sample counts and fewer epochs for architecture smoke
    tests;
  \item use \code{--cycle-ns} with \code{--skip-train-refire} to remove the
    diagnostic post-write refire window only after a matched 16 ns control is
    available;
  \item only use a coarser \code{--tran-step-ps} after a matched standard-step
    control shows the same direction, accuracy, and class histogram.
\end{enumerate}
For confirmation runs, 5--7.5 ps is now a better default than 10 ps when wall
time is acceptable.

The first Xyce comparison is promising for throughput but not a sufficient
oracle by itself.  A user-local Xyce 7.10 serial install runs the same
20-sample calibration roughly twice as fast as ngspice: about 20 s instead of
42 s at the 10 ps setting.  However, the first measured learning outcome was
85\% at both 10 ps and 5 ps, while ngspice gave 90\% at 10 ps and 95\% at
5 ps.  A later primitive pass found two concrete sources of confusion: the
tiny simulator smoke test reused a single filename, so parallel ngspice/Xyce
checks could race, and the output-bias write cell had the opposite branch
orientation from the per-synapse row cell.  After those fixes, the isolated
readout-write and composed readout/error/write primitives agree between
ngspice and Xyce to about \(10^{-5}\,\mathrm{V}\) on the key signed row and
bias deltas.  The remaining rule is stricter: any promising architecture must
pass a matched ngspice/Xyce primitive or small-training gate before it counts as
evidence.  When both simulators agree on a bad result, as in the current
3-class readout-only gate, the problem should be treated as circuit/learning
fragility rather than numerical disagreement.  The implementation now depends
on spicelib and keeps the circuit generator shared by converting generated decks
through a raw-deck adapter boundary before simulator-specific rendering.
The adapter preserves one device/connectivity body, includes ngspice
\code{.control}/\code{.endc} blocks only for ngspice, strips them for Xyce, and
compares both prepared decks with a canonical circuit-body test.
The migration point is the shared runner, not simulator-specific duplicated
generators: the active XOR/random-hidden, readout-transfer, readout-error-loop,
softmax-current-competition, reusable device primitive scripts, and older
MNIST transient/op runners now write their decks through this spicelib-backed adapter rendering
boundary before invoking ngspice or Xyce.

\section{Primitive Circuit Model}

The primitive state variables are voltages on capacitors:
\[
  w_{ij}^+,\; w_{ij}^-,
  \quad
  a_i,
  \quad
  \phi_i,
  \quad
  \delta_j,
  \quad
  g_{ij}^+,\; g_{ij}^- \;\; \text{when gradient accumulators are used.}
\]
Signed weights are represented differentially:
\[
  w_{ij} \propto V(C_{w^+}) - V(C_{w^-}).
\]
The direct-flow branch tries to remove explicit gradient accumulators by using
the backward/write window itself as the local update event:
\[
  \Delta V(C_{w^\pm}) \approx F(\phi_i,\delta_j,\mathrm{bwd},\mathrm{apply}).
\]
The update primitive must also define what happens when both signed error rails
are partially on.  A raw two-rail MOS stack can move the signed weight even
when \(\delta^+\) and \(\delta^-\) are both high; in the isolated signed
learning-cell test, equal high rails produced a large negative update.  The
newer isolated cell adds a mutually inhibited write-rail primitive so that a
positive update path is enabled only when the negative error rail is low, and
conversely.  The robust version uses two pieces: a PMOS source inhibit and an
NMOS conflict-kill device that actively discharges the generated write rail
when the opposite raw error rail is high.  That turns conflicting rails into
``no local write'' rather than an accidental depression/potentiation event.

The same idea is now available in the composed direct-flow generator as
\code{--write-error-exclusion pmos\_inhibit}.  It creates transistor-generated
\(\mathrm{rwpos}/\mathrm{rwneg}\) rails for readout writes and
\(\mathrm{hwpos}/\mathrm{hwneg}\) rails for hidden writes:
\[
  \mathrm{rwpos}_k \approx \mathrm{dp}_k \land \neg \mathrm{dn}_k,
  \qquad
  \mathrm{rwneg}_k \approx \mathrm{dn}_k \land \neg \mathrm{dp}_k.
\]
For diagnosis the generator also accepts independent readout-write and
hidden-write exclusion overrides, each with its own width override.  This lets
the readout and hidden-write paths be tested without forcing the same extra
loading onto both.
The hidden write rails use the same construction with
\(\mathrm{hdp}/\mathrm{hdn}\).  This is still a MOS-shaped rule, not ideal
logic; the point is to make ambiguous error states weak/no-write states before
they touch persistent weight capacitors.
The standalone primitive sweep can now be run with
\code{--exclusive-delta-gate}; in that mode the balanced high-error case moved
the signed weight by only \(8.2\times10^{-7}\,\mathrm{V}\), while the monotone
positive/negative input and delta sweeps still passed.  This makes the
mutual-inhibit block a good isolated synapse primitive, even though the
composed network still has to decide whether the added gating delay and loading
help or hurt a given write path.

A separate write-rail-only sweep exposed why the first composed exclusive runs
were weak: the PMOS-only source inhibit left the generated rails floating high
under balanced high \(\mathrm{dp}/\mathrm{dn}\).  Adding the NMOS kill devices
fixed the isolated block.  With \(0.1\,\mathrm{fF}\) rail capacitance and
widths from \(2\) to \(32\,\mu\mathrm{m}\), the selected rail reached at least
\(1.04\,\mathrm{V}\), the unselected rail stayed below \(10^{-9}\,\mathrm{V}\),
and balanced high conflict also stayed below \(10^{-9}\,\mathrm{V}\).

The next readout-write primitive is
\code{--write-error-exclusion pmos\_inhibit\_decay}.  It keeps the exclusive
signed rails above, but adds a third transistor-generated overlap rail:
\[
  \mathrm{rwov}_k \approx \mathrm{dp}_k \land \mathrm{dn}_k .
\]
That rail does not choose a signed update.  Instead it opens a symmetric
common-mode discharge path on both readout weight branches.  The hypothesis is
that the old raw readout stack used ambiguous high-high error states as useful
weight decay/mobility, while the hard exclusive rail removed that behavior.
In the isolated sweep, the signed rails remained exclusive and the overlap
rail appeared only for high-high conflict: \(\mathrm{rwov}\) was about
\(0.678\,\mathrm{V}\) under \(\mathrm{dp}=\mathrm{dn}=1.1\,\mathrm{V}\), and
effectively zero for one-sided \(1.1/0.2\,\mathrm{V}\) cases.  The overlap
detector uses ordinary-threshold NMOS devices so weak opposite rails do not
accidentally trigger common-mode decay.

\paragraph{Compact form (planned density step).}
The same logic can be packed into a smaller per-layer device count by
pre-computing $x_{\mathrm{active},i} = x_i \wedge \mathrm{fwd}$ once per
input rail and driving every fan-out synapse from that shared node.  The
synapse drops the in-stack fwd gates and collapses to a
$(w^+,\, x_{\mathrm{active}})$ stack from $V_{DD}$ and a symmetric
$(x_{\mathrm{active}},\, w^-)$ stack to ground, plus one pass-gate NMOS per
input rail to realise the AND.  The total device count for an $N{\to}M$
layer goes from $6NM$ (tutorial form) to $4NM + N$ (compact form, accounting
for the AND), which is a strict win for any $M \geq 1$ and around a $30\%$
saving at typical fan-outs.  The tradeoff is that $x_{\mathrm{active},i}$
becomes a layer-level analog rail whose edge timing and amplitude ---
charge-injection glitches, fan-out loading --- have to be characterised
before the local phase isolation of the in-stack-fwd form can be safely
traded for the density.  For that reason the tutorial circuit in
Fig.~\ref{fig:synapse} remains the default and matches the current netlists;
the shared-rail form is the planned next density step after buffer/sizing
checks on the shared rail.  Figure~\ref{fig:synapse-compact} shows the
compact synapse with the pass-gate AND drawn explicitly so the full device
count is visible.

\section{Direct Backward/Write Flow}

The direct-flow architecture is the cleanest match to the desired hardware
story.  During the forward window, hidden and output nodes settle by charge
flow through the forward synapses.  During the backward/write window, the
output error nodes drive current backward through the readout weight capacitor
gates.  Hidden deltas are optionally latched by a local sense amplifier, and
the same window can discharge the corresponding positive or negative weight
capacitor through stacks gated by the saved pre-activation trace.

  \centering
  \begin{tikzpicture}[

\subsection{Pre-Activation Trace Variants}

The open architectural question is where the forward pre-activation evidence
lives before the backward/write window:
\begin{description}
  \item[\code{shared\_node}] the completed XOR path; a compact source-node
    trace is reused during the backward/write event.
  \item[\code{synapse\_gate}] each synapse charges its own trace capacitor
    during forward flow and uses that stored voltage as a local write gate.
  \item[\code{synapse\_consume}] each synapse also stores its own trace, but
    the backward/write path destructively reads or bleeds the trace while using
    it.  This is closer to the ``activation capacitor is emptied as it is used''
    idea, and may simplify reset/update sequencing if it remains stable.
  \item[\code{synapse\_boost}] each synapse stores the ordinary forward trace,
    and also stores a second write-gate trace that is capacitively bootstrapped
    during the backward/write window.  This is not Python sampling: the
    capacitor is charged by a MOS pass path during \code{fwd}, then the
    \code{preboost} guide rail lifts that local stored gate so low and middle
    activations can still open the write stack.
\end{description}
The per-synapse variants are more faithful to a physical synapse that carries
its own pre-activation state, but they add capacitance and write-path loading.  The

\section{MNIST Architectures That Have Worked}

\subsection{Fixed Front-End Direct-Flow Attempts}

Since learned convolutional weight sharing is not physically free in the target
architecture, the direct-flow harness supports fixed sensory transforms as
externally driven input rails: pooled pixels, Haar-like local contrast, DCT
features, and random local ReLU features.  These are not trainable shared
weights.  They are a retina-like fixed encoder feeding ordinary voltage rails
into the trainable silicon block.  Following the preprocessing note, the harness
now includes composite \code{fixed32} and \code{sensoryN} front ends.  The former
concatenates local Haar/pool features with low-frequency DCT features; the latter
adds fixed sparse random local ReLU filters.  Small MNIST-0-vs-1 subsets are often
linearly separable after this front end.  The latest per-synapse trace bridge
improves that story: on a 16-sample MNIST-0-vs-1 subset, \code{synapse\_gate}
with readout-only flow reached 93.75\%, and the full hidden-delta path reached
the same 93.75\% when hidden writes were weakened to \code{2e-7 u}.  The
standard hidden-write strength stayed at 87.5\%, and a readout charge-noise
trial collapsed, so the current bottleneck is hidden/write calibration rather
than missing front-end separability.  The newer 32-sample and fixed16-feature
controls make the bottleneck sharper: the external input rails remain linearly
separable, but the 8-cell random hidden layer often collapses that separability
before the readout can exploit it.  On the 32-sample pool2 bridge, enabling the
real hidden-delta write path moves hidden capacitors by up to 25.3 mV but still
lands at the same 78.12\% accuracy as the readout-only control.  A follow-up
rail-buffer mode now bypasses that compression by charging hidden activation
capacitors directly from input rails through MOS pass gates during the forward
window.  On the 32-sample pool2 bridge, this produces linearly separable hidden
activations.  The first random-readout rail-buffer runs still fell to 50\%,
but the later target-mistake/interleaved runs reached 96.875\% on the
32-sample bridge with readout-only direct flow.  The same setup with reversed
readout-flow polarity collapsed to 50\%, so the sign convention is now partly
calibrated.  Adding the real hidden-delta path back in with damped hidden-delta
transport nodes keeps the same 96.875\% result while moving hidden weight
capacitors by about 8.1 mV; both shared activation nodes and per-synapse stored
pre-traces work in this one-epoch diagnostic.  A programmed
\code{csv\_separator} readout reaches 100\% with a positive 14.9 mV margin and
stays at 100\% after two mistake-gated flow epochs.  This separates the present
failure into scale and margin calibration rather than basic representational
capacity, readout sign, or the existence of a transistor-level hidden backprop
path.

The historical \code{pool2} name means a fixed two-by-two spatial pooling
encoder, not a pooling layer inside the trainable SPICE network.  Python first
area-resizes MNIST to \(8\times 8\), splits it into four \(4\times 4\) quadrants,
and drives the four quadrant-average voltages as input rails.  A transistor-level
version of this front end can be implemented as a switched-capacitor average:
sample pixel voltages onto equal capacitors, short the local capacitor bank onto
a pool capacitor, then present the pooled voltage to the synapse array.  A
resistive/conductive summing node plus integration capacitor is the current-mode
alternative.

\subsection{Relation To The Rigorous Gradient-Flow Contract}

The intended mathematical target for the dense path is the usual one-hidden-layer
ReLU model:
\[
u = Ax + b_h,\qquad h=\rho(u),\qquad y=Bh+b_o,\qquad e=t-y,
\]
with local gradient-flow writes
\[
\dot B_{kj}=\eta e_k h_j,\qquad
\dot A_{ji}=\eta \delta_{h,j}x_i,\qquad
\delta_h=\rho'(u)\odot B^T e.
\]
The clean reference contract is therefore: signed synapses implement \(W\)
forward and the corresponding weight-transport relation backward, output-error
cells form \(e=t-y\), ReLU neurons store and reuse the active mask, and each
synapse writer injects charge proportional to a local pre-value times a local
post-error.  The backward path does not have to reuse the literal same wires as
the forward path.  What matters mathematically is that the backward branch is
controlled by the same stored weight state and has a matched transfer function.
In a hardware-native model this means
\[
g^{\mathrm{bwd}}_{ji}(V_w^+,V_w^-)
\approx
\kappa\, g^{\mathrm{fwd}}_{ji}(V_w^+,V_w^-)
\]
for a known layer gain \(\kappa\).  If that matching is assumed or measured, the
separate backward stack is a valid \(W^T\)-like transport path for the hardware
model.

\subsection{Hardware-Defined MOS Learning ODE}

The more rigorous model does not make the mathematical weight \(w\)
fundamental.  The fundamental object is the MOS current law.  A synapse read is
a kernel
\[
I^{\mathrm{read}}_{ji}
=
E_{\mathrm{MOS}}(\theta_{ji}, v_{\mathrm{pre},i}, v_{\mathrm{post},j}, q),
\]
where \(\theta_{ji}\) is the physical capacitor state and \(q\) is the active
clock phase.  Ordinary multiplication by a weight appears only as a small-signal
approximation, for example
\[
E_{\mathrm{MOS}}(\theta,v_{\mathrm{pre}},v_{\mathrm{post}})
\approx
G_{\mathrm{eff}}(\theta)\,v_{\mathrm{pre}}
\]
under controlled common-mode, swing, and timing assumptions.

The forward hidden phase is therefore better written as a capacitor ODE,
\[
C_u\dot u_j
=
-g_u u_j
+
\sum_i E^F_{A,\mathrm{MOS}}(\theta^A_{ji},x_i,u_j)
+
I_{b,j},
\]
followed by a MOS activation \(h_j=\Phi_{\mathrm{MOS}}(u_j)\).  The output phase
uses the same form,
\[
C_y\dot y_k
=
-g_y y_k
+
\sum_j E^F_{B,\mathrm{MOS}}(\theta^B_{kj},h_j,y_k)
+
I_{o,k}.
\]
After a fixed forward window, the circuit computes
\(y(T_F)=f_\Theta^{\mathrm{MOS}}(x)\).

The error and backward phases are likewise hardware-defined:
\[
e_k=\Psi_{\mathrm{MOS}}(t_k-y_k),
\qquad
C_r\dot r_j
=
-g_r r_j
+
\sum_k E^B_{B,\mathrm{MOS}}(\theta^B_{kj},e_k,r_j),
\]
\[
\delta_j=D_{\mathrm{MOS}}(u_j,r_j).
\]
If \(\Psi_{\mathrm{MOS}}\) is linear near zero but saturates at large residuals,
then the circuit is training a robust MOS-shaped loss, not the textbook squared
loss.  If \(D_{\mathrm{MOS}}\) differs from \(\Phi'_{\mathrm{MOS}}\), then the
hidden rule is a surrogate-gradient hardware rule.

Finally, each writable state evolves by a MOS update kernel,
\[
C_\theta\dot\theta_{ji}
=
U_{\mathrm{MOS}}(\theta_{ji},p_i,\delta_j,q),
\]
where \(p_i\) is the stored pre-synaptic trace.  For differential signed storage,
\[
w_{\mathrm{eff},ji}
=
R(\theta^+_{ji})-R(\theta^-_{ji}),
\]
and coincidence write stacks define potentiating and depressing currents rather
than exact analog products.  In this framing the chip implements the stochastic
approximation
\[
\Theta_{n+1}
=
\Theta_n+\Delta t\,U_{\mathrm{MOS}}(\Theta_n,x_n,t_n).
\]

The exact-gradient yardstick for the continuous circuit is the adjoint of the
forward MOS ODE.  If \(\dot z=f_{\mathrm{MOS}}(z,\Theta,x)\) and
\(L=\ell(z(T),t)\), then exact gradients would require the reverse circuit to
implement
\[
-\dot a =
\left(\frac{\partial f_{\mathrm{MOS}}}{\partial z}\right)^T a,
\qquad
\nabla_\Theta L =
\int_0^T
\left(\frac{\partial f_{\mathrm{MOS}}}{\partial \Theta}\right)^T a(t)\,dt.
\]
The current hardware is not claiming that exact adjoint.  The practical
requirement is weaker: forward/backward signal alignment and update sign
alignment in the operating region.  The key characterization targets are:
\[
\frac{\partial E_{\mathrm{MOS}}}{\partial \theta^+}\ge 0,\qquad
\frac{\partial E_{\mathrm{MOS}}}{\partial \theta^-}\le 0,
\]
\[
G^B_{ij}
=
\frac{\partial E^B_{\mathrm{MOS}}}{\partial v_{\mathrm{err},j}}
\approx
\kappa
\frac{\partial E^F_{\mathrm{MOS}}}{\partial v_{\mathrm{pre},i}}
=
\kappa G^F_{ji},
\]
or at least a positive alignment
\(\langle G^B e,(G^F)^T e\rangle>0\).  The write kernel should also satisfy
\[
\operatorname{sign}(\dot w_{\mathrm{eff},ji})
\approx
\operatorname{sign}(p_i\delta_j)
\]
over the useful voltage range, with bounded state dynamics and tolerable read
disturb.  These are the SPICE characterization plots to add next: forward read
current, reverse read current, update sign/magnitude versus state, read disturb,
and retention.

\subsection{Analytic Parameter-Range Framework}

The experiment loop should not choose damping and write parameters by blind
trial and error.  The SPICE netlists remain the ground truth, but a useful
first-pass theory screens parameters by four local constraints:
\[
  \text{signal margin},\qquad
  \text{transient damping},\qquad
  \text{write mobility},\qquad
  \text{gradient stability}.
\]
The helper module \code{spice/parameter\_theory.py} implements the arithmetic in
the same units as the device runner flags: femtofarads, nanoseconds,
microamps, and ohms.

For any capacitor integration node,
\[
  \Delta V = \frac{I T}{C}.
\]
With \(I\) in microamps, \(T\) in nanoseconds, and \(C\) in femtofarads, the
numeric value is already in volts.  This gives immediate cap-sizing rules.  If
the largest expected current \(I_{\max}\) should not move the node by more than
\(V_{\max}\), then
\[
  C \ge \frac{I_{\max}T}{V_{\max}}.
\]
If the smallest useful current \(I_{\min}\) must still create at least
\(V_{\min}\), then
\[
  C \le \frac{I_{\min}T}{V_{\min}}.
\]
The feasible interval
\[
  \frac{I_{\max}T}{V_{\max}}
  \le C \le
  \frac{I_{\min}T}{V_{\min}}
\]
is the basic signal-margin test for hidden pre-activation caps, hidden-delta
caps, output score caps, pre-trace caps, and future spike-arrival storage nodes.
A larger capacitance is more numerically calm but reduces useful voltage swing
for a fixed current pulse; a smaller capacitance gives more swing but is more
sensitive to charge injection, noise, and ngspice timestep collapse.

For a damping capacitor with a weak leak resistor, the time constant is
\[
  \tau = RC.
\]
In the device-runner units this is
\[
  \tau_{\mathrm{ns}}
  =
  R_{\Omega} C_{\mathrm{fF}} 10^{-6}.
\]
If the node is active for \(T_a\) and leakage should remove at most fraction
\(\epsilon_a\) during that active window, then
\[
  \tau \ge \frac{T_a}{-\log(1-\epsilon_a)}.
\]
If old charge must passively decay to residue \(\epsilon_i\) during an idle
window \(T_i\), then
\[
  \tau \le \frac{T_i}{-\log(\epsilon_i)}.
\]
Together they imply
\[
  \frac{T_a}{-\log(1-\epsilon_a)}
  \le
  RC
  \le
  \frac{T_i}{-\log(\epsilon_i)}.
\]
If this interval is empty, a passive leak cannot both preserve the active
signal and reset the node; the circuit needs an explicit reset or bleed phase.

This immediately explains the hidden-delta damping scale that recently worked.
The stabilized runs used
\[
  C_{\mathrm{hd,int}}=0.02\,\mathrm{fF},
  \qquad
  R_{\mathrm{hd,int}}=1\,\mathrm{G}\Omega,
\]
so
\[
  \tau = 20\,\mathrm{ns}.
\]
For a \(2\,\mathrm{ns}\) useful backward/write segment, the passive loss is
\[
  1-\exp(-2/20) \approx 9.5\%.
\]
That is enough leakage to give each hidden-delta stack node a DC path and enough
capacitance to tame fast internal-node jumps, but it does not strongly erase
the backward signal during the active window.  It also shows a risk: if the
only reset mechanism were passive leakage over an \(11.2\,\mathrm{ns}\) sample
cycle, the residual would still be \(\exp(-11.2/20)\approx 57\%\).  Therefore
this damping choice is valid as a stabilization element only if phase devices
or explicit reset paths prevent stale internal-node charge from becoming state.
That should be measured directly in the next hidden-delta probes.

The generator now exposes that distinction explicitly.  The internal
hidden-delta damping nodes can be given three independent physical elements:
\[
  C_{\mathrm{hd,int}}, \qquad
  R_{\mathrm{hd,int}}, \qquad
  M_{\mathrm{reset,int}}(\mathrm{rste}).
\]
The capacitor and leak resistor stabilize floating MOS-stack nodes during the
backward window.  The optional \(\mathrm{rste}\)-gated reset transistor clears
those same internal nodes during the error/reset phase.  This is analytically
different from making the leak stronger: a stronger leak lowers \(\tau\) and
therefore attenuates the active backward signal, while a reset transistor can be
strong during reset and off during the useful backward/write interval.  The
current theory-guided pool therefore compares: damped/no internal reset,
damped/explicit internal reset, and damped/reset with weaker hidden writes.

The second analytic constraint is write size.  A local hardware update induces
\[
  \Delta w_{\mathrm{eff}}
  \approx
  \mu_{\mathrm{HW}}(\theta,a,\delta)\,a\delta,
\]
where
\[
  \mu_{\mathrm{HW}}
  =
  G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)T_{\mathrm{write}}
\]
for the raw state-dependent write model.  For a linear readout trained with
squared error, fixed-step gradient descent is stable in the batch idealization
when
\[
  0 < \eta_{\mathrm{eff}} < \frac{2}{\lambda_{\max}(X^T X)}.
\]
For a single sample this reduces to
\[
  \eta_{\mathrm{eff}} < \frac{2}{\|a\|^2}.
\]
The hardware is not exact SGD, but this bound is still a useful scale test: if
the measured per-example \(\Delta w_{\mathrm{eff}}/(a\delta)\) is above this
range, the write path is likely to overshoot or destroy margins; if it is far
below the noise and read-disturb floor, the classifier will stall even on a
linearly separable feature set.  This is a better way to choose
\code{readout-update-width-u}, \code{hidden-update-width-u}, write-window
duration, and branch-specific write rails.

The third constraint is backward alignment.  Let \(G^F\) be the forward
small-signal read gain and \(G^B\) the backward error-flow gain produced by the
same stored capacitor states or by a matched backward stack.  The ideal target
is
\[
  G^B \approx \kappa (G^F)^T,
\]
but useful learning only needs positive alignment,
\[
  \cos\alpha
  =
  \frac{\langle G^B e,(G^F)^T e\rangle}
       {\|G^B e\|\|(G^F)^T e\|}
  > 0
\]
over the error vectors that actually occur.  This gives a quantitative
criterion for deciding whether a separate backward stack is good enough: sweep
stored weight states, drive representative error rails, measure \(G^B\), and
compare it with the forward small-signal transpose.  If the cosine is negative
or near zero, scaling hidden training will not work no matter how carefully the
write cap is tuned.

The fourth constraint is mobility conditioning.  For signed differential
branches,
\[
  w_{\mathrm{eff}}=G^+(\theta^+)-G^-(\theta^-),
\]
the useful update mobilities are
\[
  \mu_+ =
  G^{+\prime}(\theta^+)s^+_{\mathrm{MOS}}(\theta^+),
  \qquad
  \mu_- =
  G^{-\prime}(\theta^-)s^-_{\mathrm{MOS}}(\theta^-).
\]
The operating window should satisfy sign alignment and a bounded condition
ratio,
\[
  \mu_+>0,\quad \mu_->0,\quad
  \frac{\min(\mu_+,\mu_-)}{\max(\mu_+,\mu_-)}
  \ge \rho_{\min}.
\]
This does not require the chip to compute \(G'\).  It says that the chosen
capacitor-voltage window and write primitive must place the physical cell in a
region where the natural MOS mobility is not rail-pinned, one-sided, or
unmeasurably small.

The resulting workflow is:
\begin{enumerate}
  \item Use the signal-margin inequalities to choose candidate caps and clock
    windows before running full training.
  \item Use the RC bounds to choose damping that preserves active signals and
    either passively clears stale charge or forces an explicit reset.
  \item Use cell sweeps to measure \(G^F\), \(G^B\), and
    \(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) in the candidate state window.
  \item Convert measured write motion into an effective \(\eta_{\mathrm{eff}}\)
    and compare it with \(2/\lambda_{\max}(X^TX)\) for the current task.
  \item Only then launch the full training pool.
\end{enumerate}

\subsection{Controls Before Trusting Accuracy}

A high transient accuracy is not by itself evidence of hardware-native
learning.  Every promising result should be paired with controls that can
falsify the easiest misleading explanations:
\begin{center}
  \begin{tabular}{p{0.30\linewidth}p{0.58\linewidth}}
    \toprule
    Control & What it tests \\
    \midrule
    Reversed-polarity negative control &
    The update sign matters; reversing \(\mathrm{dp}/\mathrm{dn}\) should
    collapse or clearly degrade. \\
    Readout-only vs full-hidden &
    Hidden writes help only if full-hidden beats or changes the readout-only
    anchor for the right reason. \\
    Per-synapse trace, hidden writes off &
    Separates trace-cap loading from actual lower-layer learning. \\
    Programmed separator &
    Confirms the readout circuit can express the target separator before
    blaming training. \\
    No-write checkpoint evaluation &
    Detects transient optima, drift, and overtraining of capacitor states. \\
    Multiple seeds and sample orders &
    Prevents claiming a lucky seed or class ordering as a circuit result. \\
    Label shuffle &
    Should not train; if it does, the metric or leakage path is suspect. \\
    Device perturbation &
    Checks that the result survives mismatch/noise rather than only nominal
    LEVEL=1 parameters. \\
    \bottomrule
  \end{tabular}
\end{center}

The experiment runner now has a binary-readout control pool,
\code{v569\_v574\_controls}, that instantiates the first version of this gate:
nominal readout-only, reversed readout-flow polarity, shuffled labels,
interleaved sample order, a second seed, and per-synapse trace storage with
hidden writes still disabled.  A run should only be promoted if the negative
controls fail in the expected direction and the robustness controls stay in the
same accuracy family.

The first completed control pass is encouraging but not yet robust.  On
\code{mnist01fixed8\_64}, the nominal readout-only run reached \(79.69\%\),
reversed-polarity stayed at \(50\%\), and label-shuffle ended at \(51.56\%\).
Interleaving the same samples improved to \(85.94\%\), while seed 4 collapsed
back to \(50\%\).  Enabling per-synapse trace storage with hidden writes still
off reached \(90.625\%\).  This says the update sign and trace locality are
real, but the operating range is still seed/order sensitive.

The follow-up exclusive-write pool \code{v575\_v577\_exclusive} keeps the same
fixed input option and tests the PMOS mutual-inhibit rails in the composed
network.  It is useful but not a universal improvement at the first sizing.
The shared-node readout improved to \(85.94\%\), which is better than the
\code{v569} shared-node anchor.  The per-synapse-gated readout fell to
\(81.25\%\), and enabling hidden writes with the same exclusive rails also
ended at \(81.25\%\), with hidden signed-weight capacitors moving only about
\(6.1\,\mathrm{mV}\) at maximum.  The conclusion is narrow: mutual inhibition
is a good primitive for suppressing ambiguous local writes, but the
per-synapse/full-hidden path needs sizing or timing work before this block
should replace the previous non-exclusive readout anchor.

The first corrected write-rail generator adds explicit NMOS kill devices to
the PMOS-inhibit rails.  Isolated behavior is now clean, but readout-only
width checks \code{v580} and \code{v581} still ended at \(81.25\%\) for
\(16\,\mu\mathrm{m}\) and \(2\,\mu\mathrm{m}\) exclusion devices.  The
full-hidden run with corrected exclusive rails on both readout and hidden
writes, \code{v582}, also ended at \(81.25\%\).  In contrast,
\code{v583} kept readout writes plain, applied the corrected exclusive rail
only to hidden writes, and recovered \(90.625\%\).  That means the present
readout write block benefits from a MOS-shaped ambiguous-error region that the
hard exclusive rail removes, while the hidden-write path can use mutual
inhibition without destroying the readout operating point.  The next
architecture work should therefore treat readout write mobility and hidden
write rail selection as separate building blocks.

The overlap-decay readout primitive partially recovers the lost ambiguous-error
behavior.  Retesting hard readout exclusivity with explicit rail resets in
\code{v584} reached \(85.94\%\), so stale generated rails were part of the
problem but not the whole problem.  Adding the high-high overlap rail in
\code{v585} improved the same readout-only setup to \(89.06\%\).  This is still
below the \(90.625\%\) per-synapse trace anchor, but it supports the model that
the readout block needs a controlled common-mode decay/mobility path rather
than a pure winner-take-all signed write selector.
A small tuning pool then showed that overlap rail device width is not the
active knob: \(4\), \(8\), and \(16\,\mu\mathrm{m}\) all stayed at
\(89.06\%\).  Increasing the readout write width from \(0.00035\) to
\(0.00045\,\mu\mathrm{m}\) in \code{v589} recovered \(90.625\%\), while
reducing it to \(0.00025\,\mu\mathrm{m}\) in \code{v590} fell to about
\(70\%\).  The present model is therefore that overlap-decay fixed the write
direction/ambiguity problem, and the remaining readout-only operating point is
mostly write-mobility scale.
The same primitive composes with the hidden backward/write path.  With the
original \(0.00035\,\mu\mathrm{m}\) readout write width, \code{v586} matched
the readout-only overlap result at \(89.06\%\) while moving hidden weights by
about \(9\,\mathrm{mV}\).  Raising the readout write width to
\(0.00045\,\mu\mathrm{m}\) in \code{v591} reached \(92.1875\%\), with hidden
weights moving \(9.27\,\mathrm{mV}\).  This is the strongest fixed-input
full-hidden result in the current direct-flow branch until the next overshoot
check, \code{v592}, pushed the same architecture to \(93.75\%\) at
\(0.00055\,\mu\mathrm{m}\) readout write width.  The next useful experiment is
therefore not new preprocessing; it is a mobility-bracketing sweep around the
overlap-decay readout write block, followed by a larger fixed-input sample
count once the best mobility window is stable.
Two negative controls support that this is real learning rather than an
accuracy artifact.  Keeping the same overlap-decay readout but reversing the
write polarity in \code{v593} collapsed to \(50\%\), and shuffling labels in
\code{v594} reached only \(59.375\%\).  Those controls are not sufficient for
full robustness, but they rule out the most obvious sign-convention and metric
failures for the new readout block.

The first larger fixed-input scale check is mixed.  With the same overlap-decay
readout and \(0.00055\,\mu\mathrm{m}\) write width, the 128-sample readout-only
run \code{v595} reached only \(80.47\%\), worse than earlier 128-sample
anchors near \(91\%\).  The corresponding 128-sample full-hidden run
\code{v596} did not finish within the \(1800\,\mathrm{s}\) runner limit.  This
means the \(0.00055\,\mu\mathrm{m}\) overlap-decay setting is a good
64-sample mobility point, not yet a scalable default.  The next scale test
should bracket mobility again on 128 samples and should not assume that the
64-sample optimum transfers.

\subsection{Two-Hidden and Spiking XOR Probes}

Two small architecture probes test whether the same component language extends
past the one-hidden-layer fixed-input runs.  These are intentionally XOR-scale
SPICE experiments, not MNIST preprocessing experiments.

The two-hidden-layer probe
\code{device\_xor2\_two\_hidden\_v1\_score} uses:
\[
  \text{literal feature layer}
  \to
  \text{trainable hidden layer 2}
  \to
  \text{trainable readout}.
\]
Layer 1 is still a fixed literal detector bank, so this is not a free
feature-discovery MLP.  It is a transport and composition test.  The circuit
computed nonzero hidden-2 deltas and nonzero hidden-1 deltas on every training
cycle, and the hidden-2/readout score caps separated all four XOR patterns.
The initial score accuracy was \(100\%\), the final score accuracy was
\(100\%\), and training increased the minimum score margin from
\(29.3\,\mathrm{mV}\) to \(45.4\,\mathrm{mV}\).  The first buffered-output
version used an \code{NREL} output follower, and the score voltages
(\(\approx 3.8\)--\(49\,\mathrm{mV}\)) sat below that follower's threshold, so
the output nodes tied at \(0\%\).  Re-running the same circuit with an
\code{NSENSE} output follower in
\code{device\_xor2\_two\_hidden\_v2\_nsense\_out} fixed that scale mismatch:
initial and final output-node accuracy were both \(100\%\), and the final
minimum output margin was \(17.9\,\mathrm{mV}\).  The interpretation is still
narrow, but now cleaner: deeper forward/backward/update plumbing works on this
XOR probe, and the remaining lesson is that each additional layer needs an
explicit gain/threshold budget for the next stage.

The spiking/timed-output probe
\code{device\_xor2\_spiking\_v1\_weak} replaces the steady output buffer with
a leaky spike capacitor:
\[
  C_{\mathrm{spk}}\dot v_{\mathrm{spk}}
  =
  I_{\mathrm{score}\to\mathrm{spk}}(v_{\mathrm{score}})
  -
  g_{\mathrm{leak}}v_{\mathrm{spk}}.
\]
Accuracy is measured at fixed offsets in the forward window, so the correct
class only has to produce the larger transient spike voltage at the selected
time.  With weak class-coded readout initialization, timed-spike XOR started at
\(25\%\) and trained to \(100\%\) after four epochs.  A reversed-write control
\code{device\_xor2\_spiking\_v2\_weak\_reversed} started from the same weak
condition but reached only \(50\%\), with the final mean score margin negative.
This is the expected sign-control failure: swapping the local \(\mathrm{dp}\)
and \(\mathrm{dn}\) write rails makes the update fight the target.

These probes do not prove MNIST-scale depth or spiking training.  They do show
that the present MOS-stack primitives can express a deeper hidden transport
path and a transient output code without introducing Python-computed
activations, deltas, or multiplications in the signal path.

\subsection{Softmax-Like Error Normalization}

For classification, the desired cross-entropy descent signal is
\[
  e_k = t_k - p_k,
  \qquad
  p_k = \frac{\exp(s_k)}{\sum_j \exp(s_j)} .
\]
The elegant hardware version is current-mode rather than voltage-mode.  In
subthreshold CMOS, a score voltage naturally creates an exponential current,
\[
  I_k \approx I_0 \exp(\kappa V_{s,k}/U_T),
\]
and a shared source/tail or log-domain normalizer makes the branch currents
compete for a limited total current.  The branch current fraction
\(I_k/\sum_j I_j\) is then the softmax probability.  For a binary classifier
this is just a differential pair; for \(K\) classes it becomes a
source-coupled or soft-winner-take-all array.

The current LEVEL=1 ngspice models used in these notes do not model
subthreshold exponentials well, so the first primitive is deliberately weaker:
\code{device\_softmax\_current\_competition\_v1\_smallmargin} uses three
source-coupled \code{NREL} branches and a shared NMOS tail device.  There is
no behavioral \(\exp\) or divide in the signal path.  Python computes current
shares only after the run for characterization.  With equal scores, the three
shares are exactly one third in the measured operating point.  With small
score offsets, the shares move smoothly and preserve the argmax:
\[
  (0.38,0.35,0.35)\,\mathrm{V}
  \mapsto
  (0.457,0.271,0.271),
\]
\[
  (0.42,0.38,0.35)\,\mathrm{V}
  \mapsto
  (0.551,0.295,0.155).
\]
Large score differences collapse toward winner-take-all, which is also useful
to know: with these strong-inversion toy models, the normalizer is a
softmax-like positive-current competition only in the small-margin range.  A
real subthreshold/PDK model should be characterized before using this as the
multiclass error block.

The first version consumed one single-ended score per class, but the current
network stores split score capacitors \(\mathrm{scorep}_k,\mathrm{scoren}_k\).
The adapter-rendered diagnostic now includes a split-score competition cell:
\(\mathrm{scorep}_k\) opens the class branch, while \(\mathrm{scoren}_k\)
inhibits the same branch through a PMOS source device.  This avoids a Python
subtraction before the softmax-like competition.  It is still not textbook
softmax: the measured branch current is a MOS-defined function
\[
  I_k = C_{\mathrm{MOS}}(\mathrm{scorep}_k,\mathrm{scoren}_k,V_{\mathrm{tail}})
\]
and probabilities are only characterized after the run as current shares.
The useful criterion is therefore monotone signed-score ordering and reasonable
common-mode tolerance, not equality to \(\exp(s_k)/\sum_j\exp(s_j)\).
The first split-score run is a useful negative result: ngspice and Xyce agree
to measurement precision through the adapter-rendered deck, but the simple
branch/inhibit topology preserves ordering only when \(\mathrm{scoren}\) is
held fixed.  When both split rails move, or when common mode changes at fixed
\(\mathrm{scorep}-\mathrm{scoren}\), absolute \(\mathrm{scorep}\) still
dominates too strongly.  This cell is therefore a simulator-consistency and
characterization primitive, not yet the multiclass error block to insert into
the learner.

The next split-score normalizer is a local source-coupled differential pair per
class.  Each class first compares \(\mathrm{scorep}_k\) against
\(\mathrm{scoren}_k\) through a matched NMOS pair with its own tail device, and
only the positive-branch current enters the class current share.  In the
LEVEL=1 model this is still not a proof of softmax, but it is much better at
rejecting common-mode score motion.  The default diagnostic
\code{device\_softmax\_current\_competition\_diffpair\_default} uses
\(V_{\mathrm{tail}}=0.42\,\mathrm{V}\), \(W_{\mathrm{tail}}=32\,\mu\mathrm{m}\),
and \(W_{\mathrm{branch}}=12\,\mu\mathrm{m}\).  On a seven-case stress table,
including cases where a lower absolute \(\mathrm{scorep}\) has a larger
\(\mathrm{scorep}-\mathrm{scoren}\), it preserves every non-tie argmax.  The
total current still moves by about 15.9\%, so this is a candidate current
competition block, not a solved probability generator.

For the direct-flow learner, the intended cross-entropy-style write rails are:
\[
  \mathrm{dn}_k \propto p_k \quad (k \ne y),
  \qquad
  \mathrm{dp}_y \propto 1 - p_y.
\]
That replaces the present score/L2-like residual rail with a normalized
competition rail while keeping the local synapse update unchanged:
\(\dot w_{ki}\propto (t_k-p_k)a_i\).

The score used to select circuit variants should therefore combine accuracy
with hardware-native learning quality:
\begin{align*}
  \text{score}
  ={}& \text{accuracy}
  - \lambda_1 \text{(bad negative controls)}
  - \lambda_2 \text{(wrong update sign)} \\
  &- \lambda_3 \text{(poor backward alignment)}
  - \lambda_4 \text{(rail-pinned mobility)}
  - \lambda_5 \text{(ngspice failures)}.
\end{align*}
In practice the diagnostic gates are: local update sign is correct, write
magnitude is in range, event gates open only when they should, backward
transport is positively aligned, state remains in a useful mobility window,
ngspice converges, and performance survives scale and variation.

\subsection{Compact Forward Synapse Candidate}

The running netlists keep the forward phase gate inside every signed synapse
branch.  For the hidden forward path this gives a tutorial-clean six-MOS cell:
input gate, weight gate, and \code{fwd} gate on the positive branch, mirrored by
\code{fwd}, input gate, and negative-weight gate on the negative branch.  A
reasonable density step is to precompute a shared active input rail
\[
x^{\mathrm{active}}_i = x_i \wedge \mathrm{fwd}
\]
once per input rail, then feed that rail to every fan-out synapse.  The per-cell
forward stack becomes weight plus \(x^{\mathrm{active}}\) on each signed branch,
so the count changes from roughly \(6NM\) devices to \(4NM+N\) devices for an
\(N\)-input, \(M\)-hidden layer.

This is a good compact form, but it changes what must be characterized.  The
shared \(x^{\mathrm{active}}\) rail now carries fan-out load, edge timing,
charge injection, and any \code{fwd} glitch to every postsynaptic cell.  The
current six-MOS form keeps phase isolation local and is easier to debug.  The
compact form should therefore be introduced as an area-optimized variant after
the shared active-rail amplitude, delay, and backward-window leakage paths are
measured.

The 96.875\% \code{mnist01\_32} rail-buffer result is only a partial match to
that contract.  It does use capacitor-held signed weights, ngspice-generated
output-error rails, readout-weight-transport hidden deltas, hidden activation
gating, and local direct-flow writes.  It does not yet use learned
\(h=\rho(Ax+b_h)\) hidden features: \code{rail\_buffer} copies the four input
rails into hidden activation capacitors through MOS pass gates.  Its error rule,
\code{out\_competitive} plus target-mistake gating, is closer to a margin/mistake
update than exact analog \(e=t-y\).  The backward transport is implemented by
separate transistor stacks controlled by the same readout weight-capacitor
voltages.  That is architecturally acceptable; the remaining rigor gap is that
we have not yet measured or constrained the forward and backward MOS transfer
functions enough to claim an exact gain-matched \(W^T\) operator.  The local
write cell is also a series-gated charge/discharge product approximation, not an
ideal four-quadrant analog multiplier.  This is why the result should be read as
a strong device-level bridge and hardware-native learning rule rather than a
completed proof of exact textbook analog SGD.

This distinction is mathematical, not a sign that the circuit is doing
non-physical or behavioral arithmetic.  The ideal reference rule is
\[
e_k=t_k-y_k,\qquad \dot w_{ji}=\eta\,\delta_j a_i.
\]
The MOS implementation instead defines hardware transfer functions.  A compact
way to write the actual learning rule is
\[
e^{\mathrm{hw}}_k =
E_{\mathrm{MOS}}\!\left(t_k,y_k,V_{dp,k},V_{dn,k};\theta_E,T_E\right),
\]
\[
\dot V^{+}_{w,ji}-\dot V^{-}_{w,ji}
=
U_{\mathrm{MOS}}\!\left(a_i,e^{\mathrm{hw}}_j,V^+_{w,ji},V^-_{w,ji};
\theta_U,T_U\right),
\]
where \(E_{\mathrm{MOS}}\) and \(U_{\mathrm{MOS}}\) are set by threshold
voltages, stack headroom, capacitances, device widths, and integration windows.
In the small-signal limit they are intended to be monotone approximations to
\(t_k-y_k\) and \(a_i\delta_j\), but at full swing they are saturating,
state-dependent nonlinear maps.  This is acceptable if it trains well: the chip
is better viewed as training a hardware-native neural model with MOS-shaped
forward, error, backward, and update functions, rather than as exact gradient
descent on the textbook squared-error ReLU network.

Similarly, not every signal needs a differential pair.  Signed quantities such
as weights and errors benefit from positive/negative capacitor rails.  ReLU
activations and score capacitors can be single-ended nonnegative voltages without
breaking the model; that simply means the implemented network is a rectified,
single-ended hardware model wherever the mathematical variable is constrained to
be nonnegative.

To test the specific error-generation gap, the generator now has an
\code{out\_residual} mode.  Unlike \code{out\_competitive}, which gates the target
class by the competing output, \code{out\_residual} uses each class's own stored
output capacitor when forming the positive and negative error rails.  It is still
a transistor-stack approximation, but it is much closer to the intended
\(e_k=t_k-y_k\) circuit contract.  The first residual experiments show the
tradeoff clearly.  On XOR, scheduled \code{out\_residual} direct flow solves the
task at 100\% with a \(+12.2\ \mathrm{mV}\) margin.  On the 32-sample
MNIST-0-vs-1 rail-buffer bridge, scheduled residual updates collapse to 50\%.
Reusing the target-mistake backward gate recovers 93.75\% for both the
readout-only control and the all-layer per-synapse-trace run, but still trails
the 96.875\% \code{out\_competitive} bridge.  A first sizing sweep then raised
the residual output-feedback stack from \(64\,\mu\mathrm{m}\) to
\(128\,\mu\mathrm{m}\), keeping the target/source stack at \(96\,\mu\mathrm{m}\).
That readout-only run recovered 96.875\%, matching the competitive bridge.  Thus
the residual cell is wired and useful, but its MOS error shape is sensitive to
device sizing and timing.

\subsection{Readout Mobility Diagnosis}

The 64-sample fixed-feature results exposed a simpler blocker than hidden
representation capacity.  The \code{fixed8}, \code{dct16}, and
\code{fixed32} input features are linearly separable, but the natural
discharge-only MOS readout update stalls between 81\% and 84\%.  That makes the
readout state map itself suspect.

The right local model separates two derivatives.  If a stored capacitor state
\(\theta\) produces an effective read conductance
\[
  w_{\mathrm{eff}} = G_{\mathrm{eff}}(\theta),
\]
then backward error flow to the previous neuron uses the forward small-signal
gain \(G_{\mathrm{eff}}\).  The physical capacitor update, however, changes the
stored state \(\theta\), so its effect on the usable weight is
\[
  \dot w_{\mathrm{eff}}
  =
  G'_{\mathrm{eff}}(\theta)\,\dot\theta .
\]
For a real MOS write stack, the update is better written as
\[
  \dot\theta
  =
  \eta\,\delta a\,s_{\mathrm{MOS}}(\theta),
  \qquad
  \dot w_{\mathrm{eff}}
  =
  \eta\,\delta a\,G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta).
\]
The product \(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) is the effective learning
mobility.  If it is tiny, saturated, or asymmetric between the positive and
negative read branches, a sign-correct update can still fail to move the
effective classifier enough.

There are two different derivatives here.  The backward error sent to the
previous neuron is controlled by the read kernel's small-signal gain with
respect to the pre-activation.  In the linearized case
\(E_{\mathrm{MOS}}(\theta,a)\approx G_{\mathrm{eff}}(\theta)a\), this gain is
\(\partial E_{\mathrm{MOS}}/\partial a=G_{\mathrm{eff}}(\theta)\), so reverse
error flow should use the effective conductance itself.  The physical state
update is controlled by the read kernel's sensitivity to the stored state:
\(\partial E_{\mathrm{MOS}}/\partial\theta
=aG'_{\mathrm{eff}}(\theta)\).  Thus \(G_{\mathrm{eff}}\) belongs in the
backward path, while \(G'_{\mathrm{eff}}\) belongs in the state-mobility or
write-compensation analysis.

The present charge+discharge readout write does not explicitly implement
\(S(\theta)=G'_{\mathrm{eff}}(\theta)\), and it also does not implement a
damped pseudo-inverse of \(G'_{\mathrm{eff}}\).  It is closer to the raw
hardware rule \(S(\theta)=s_{\mathrm{MOS}}(\theta)\): the same local
pre-activation and error gates choose the update sign, while the MOS stack,
stored capacitor voltage, headroom, and timing determine the update magnitude.
That is a legitimate hardware-defined learning rule, but it means a linearly
separable feature set can still train poorly if the induced mobility
\(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) is badly conditioned.

The new \code{device\_readout\_mobility\_v0} sweep characterizes that effect
directly in ngspice.  At \(a=0.5\), the positive read branch has useful slope
near \(\theta=0.24\) to \(0.58\ \mathrm{V}\), but is nearly flat by
\(\theta=0.82\ \mathrm{V}\).  The negative branch in this single-branch probe
changes abruptly near \(0.10\) to \(0.16\ \mathrm{V}\) and is essentially flat
above \(0.24\ \mathrm{V}\).  The direct write discharge also changes by about
an order of magnitude over the same state range.  The current default random
readout initialization, roughly \(0.56\) to \(0.72\ \mathrm{V}\), therefore
starts near the high branch's saturation shoulder and far outside the negative
branch's measured slope window.  That is a plausible explanation for why the
64-sample readout can move capacitor voltages by roughly \(0.1\ \mathrm{V}\)
yet still under-correct the effective class separator.

This does not mean the circuit must compute \(G'\) explicitly.  The first
prototype strategy is to keep \(\theta\) in a measured high-mobility window and
let the MOS write stack implement its natural state-dependent mobility.  Later
versions can add state-dependent write pulse width, a local compensation
transistor, or a damped pseudo-inverse update if the raw mobility remains too
asymmetric.

Centered-initialization controls show the coupled circuit problem.  Moving the
random readout down to \(0.24\ \mathrm{V}\) with a \(0.16\ \mathrm{V}\) span
ended at 40.625\% and produced only \(0.20\ \mathrm{mV}\) of signed readout
movement; the output sense latch stayed effectively both-high, so the
mistake-gated backward rail barely opened.  Centering at \(0.16\ \mathrm{V}\)
with a \(0.08\ \mathrm{V}\) span also barely opened the backward rail and ended
at 51.5625\%.  Centering at \(0.34\ \mathrm{V}\) gave more write motion
(\(26.3\ \mathrm{mV}\)) but only 45.3125\% final accuracy.  So the operating
point must satisfy both conditions at once: useful \(G'_{\mathrm{eff}}\) in the
weight cells and enough forward score/output swing for the transistor error
and lead-gate circuits to generate a real backward stream.

Separate output-head controls support the same conclusion.  Scaling the output
forward path did not rescue the low-state readout window: the
\code{center024\_outgain4} run ended at 40.625\% with only
\(10.3\ \mu\mathrm{V}\) mean backward signal, and the
\code{center034\_outgain3} run ended at 43.75\% even though the backward stream
opened to \(0.382\ \mathrm{V}\).  A \(2\times\) output-gain run with the
default random readout moved the signed readout by \(163\ \mathrm{mV}\), but
fell to 67.1875\%.  More movement is therefore not sufficient unless the
movement is aligned with the effective separator and the output decision
circuit remains in range.

Naively precharging the score capacitors to \(0.30\ \mathrm{V}\) also failed:
three score-common-mode controls ended at 0\% with zero final margin.  The
single-ended output follower currently treats score common-mode as signal
rather than rejecting it.  The next readout head should therefore be
differential, or include an explicit common-mode-rejecting subtract stage, so
negative readout branches get discharge headroom without collapsing the class
comparison.

The next prototype adds two circuit options.  The
\code{score\_diff} output head charges each class output from its own score
and discharges it through the competing score, giving a small
common-mode-rejecting output stage.  The
\code{charge\_discharge} direct-flow write mode makes a positive local update
charge \(w^+\) while draining \(w^-\), and a negative update do the reverse.
This matters because the previous direct-flow readout update was
discharge-only: balanced training data can drain both signed branches until the
effective classifier collapses.

On the 8-sample \code{fixed8} MNIST-0-vs-1 subset, score-diff alone remained at
50\% with only \(14.2\ \mu\mathrm{V}\) mean backward signal.  A scheduled
perceptron error with the old discharge-only write moved the caps by
\(99.2\ \mathrm{mV}\), but collapsed both score nodes to the same value and
ended at 12.5\%.  With the bidirectional charge+discharge write, the same
score-diff/perceptron setting reached 100\% final accuracy with
\(+8.08\ \mathrm{mV}\) minimum margin.  This is not yet the MNIST solution, but
it is strong evidence that signed capacitor writes need a bidirectional
physical update, not only selective discharge.

Scaling that same setting to 16 samples exposes the next blocker.  The
\code{rw002/e2} run dropped from 62.5\% initial accuracy to 50\% with a
\(-121\ \mathrm{mV}\) final margin.  Reducing the write width to
\code{0.0005u} and one epoch ended at 56.25\%, and interleaving the class order
still ended at 50\%.  So charge+discharge fixes the signed-storage collapse, but
the linear readout still needs better step-size, state-mobility, or error-gating
control before it is stable on larger separable subsets.

The next circuit-side fix was timing, not another Python-side error rule.  The
first target-mistake controls compared after the forward window, when the
\code{score\_diff} outputs had collapsed to tens of millivolts.  The lead nodes
therefore stayed effectively both-high and the transistor backward rail was only
microvolts.  The generator now exposes \code{cmp-start-ns}, and the
\code{target\_mistake} gate now derives its winner polarity from the selected
lead circuit.  This lets the score sense amplifier compare while the forward
score is still live.  The readout-stack internal nodes now also have explicit
small parasitic capacitors and leakage paths, matching the hidden stacks and
removing a late transient singularity on floating readout nodes.  With early
score comparison, the readout-only
\code{device\_mnist01fixed8\_8\_v283\_earlyscore\_targetmistake\_parasitic\_charge\_rw001\_e4}
run reached 100\% on the 8-sample \code{fixed8} subset with
\(+2.58\ \mathrm{mV}\) final margin.  The backward/write rail in that run is
generated by target, score-sense, and \code{bwd\_src} transistor stacks, not by a
scheduled Python \code{bwd} source.  The same current circuit reaches 81.25\% on
the 16-sample fixed8 subset, so the next limiter is again step control and
readout mobility, not the existence of a transistor-generated backward rail.

The best follow-up 16-sample run so far is \code{v289}, the interleaved
early-score target-mistake run with \code{rw0005} and four epochs.  It reached
87.5\%.  Longer training or nearby timing changes did not improve it: six
epochs fell back to 81.25\%, moving the compare window earlier dropped to
75\%, moving it later stayed at 81.25\%, and a mistake-latch variant reached
75\%.  The instrumented runs show backward rails near a volt, but also several
false target-mistake openings or missed openings per training sequence.  This
is consistent with the \(G_{\mathrm{eff}}\) vs.\ \(G'_{\mathrm{eff}}\) diagnosis:
the readout is no longer starved of backward current, but the state-dependent
write mobility and imperfect gate timing still make the effective separator
move unevenly.

The next circuit probe added optional center-pull devices on the readout state
itself.  During the backward/write window, weak MOS pass devices can pull
\(w^+\), \(w^-\), and optionally the output-bias capacitor states toward a
global \code{wcenter} rail.  This is a physical state path in the generated
netlist, not a Python regularizer, and it tests whether keeping \(\theta\) near
a better mobility region helps the linear readout.  The result is mixed but
useful.  Removing output-bias updates regressed to 75\%.  Gentler readout/bias
writes and score-precharge controls stayed at 87.5\%.  Center pulls of
\code{0.00005u} and \code{0.0001u} also regressed to 75\%, while
\code{0.0002u} improved the best four-epoch transient margin to about
\(-1\ \mathrm{mV}\) without improving final accuracy.  Extending the
\code{0.0002u} center-pull setting to five epochs reached 93.75\%, but the
target-mistake gate match fraction fell to roughly 0.64 with many false opens
and missed openings.  So the \(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) mobility
issue is plausibly part of the linear-readout blocker, but it is coupled to the
comparator and update-gate selectivity; a better state map alone is not enough.

The latest lead/gate sweep separates these two effects more sharply.  Direct
score-gated and charge-only score-lead variants can identify the winning score
in the diagnostics, but \code{score\_direct} only generates millivolt-scale
backward gates and the charge-only lead variants top out at 68.75\%.  The new
\code{senseamp\_strong} lead adds cross-coupled NMOS regeneration.  Its
width-64 five-epoch run improves target-mistake gate agreement to 83.75\% and
the best transient margin to about \(-0.65\ \mathrm{mV}\), but seven-epoch
extensions settle at 81.25\%; the old senseamp control reaches 75\%.  Thus the
remaining linear-readout blocker is not just representation separability or
whether the error is generated in Python.  The hardware update map itself must
be better conditioned: the target-mistake event has to be rail-level and
selective, and the selected write path has to move the effective conductance
through a useful \(G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)\) region.

The following sweep rules out two tempting fixes.  Replaying a latched mistake
event is worse than the direct flow: the original \code{target\_mistake\_latch}
variants land at 50\%, the output-cap latch falls to 31.25\%, and the new
short-stack \code{target\_mistake\_latch\_simple} variants also stay at 50\%
even when the latch diagnostic agrees with the score comparison around
76--82.5\%.  Lowering the center-pull rail is also not a direct mobility fix.
A \(0.50\ \mathrm{V}\) center rail gives the best target-mistake gate agreement
so far, 91.25\%, but accuracy still collapses to 50\%; a \(0.34\ \mathrm{V}\)
center rail collapses to 25\%.  Removing center pull reaches 75\%, and
discharge-only write modes stay at 50\%.  This separates the event path from
the state map: the circuit can make the event mostly right, but an
unconditional center pull or a coarse replayed latch does not implement the
desired state-dependent mobility.  The next useful circuit change should be
local to the selected write branch, not a global pull on every stored weight.

The first local selected-branch version is
\code{bounded\_charge\_discharge}.  Instead of pulling selected branches all the
way to \(V_{DD}\) or ground, it charges through a local \code{whigh} rail and
discharges through a local \code{wlow} rail.  This is still a transistor write
path in SPICE, but it crudely constrains the selected capacitor state to a
chosen mobility window.  On the same 16-sample fixed8 readout task, \code{v345}
with \(0.58/0.16\ \mathrm{V}\) rails reaches 81.25\%, adding a weak global
center pull reaches 87.5\%, and the \(0.70/0.24\ \mathrm{V}\) no-center setting
in \code{v347} reaches 93.75\%.  A lower \(0.50/0.10\ \mathrm{V}\) setting
falls to 68.75\%.  Tightened controls keep the same pattern:
\(0.64/0.20\ \mathrm{V}\) reaches 87.5\%, \(0.76/0.28\ \mathrm{V}\) reaches 93.75\%, and
halving the readout write width at \(0.70/0.24\ \mathrm{V}\) still reaches
93.75\% while improving the final transient margin to about
\(-4.2\ \mathrm{mV}\).  That is the clearest current evidence that the
derivative factor \(G'_{\mathrm{eff}}(\theta)\) and the MOS write mobility are
related to the linear-readout stall: changing only the physical write rails and
selected-branch write width changes the learned effective separator
substantially, even though the input and hidden features remain linearly
separable.

The first scale probes were negative.  Reusing the best 16-sample
bounded-charge-discharge setting on 32 fixed8 examples reached only 50\%, and a
quick 64-example three-epoch probe reached 53.125\%.  Both runs still reported
linearly separable input and hidden feature matrices, so this was not a feature
representation failure.

The follow-up split the selected-branch write primitive into charge only,
discharge only, and the combined charge/discharge mode.  This changed the
diagnosis.  With
output-bias writes disabled and the same \(0.70/0.24\ \mathrm{V}\) bounded rails,
charge/discharge reached 71.875\% on 64 fixed8 examples, charge only reached
65.625\%, but discharge only reached 90.625\%.  The corresponding 32-example
controls show the same ordering: charge only reached 75\%, while discharge only
reached 90.625\%.  Adding even a very small output-bias write collapsed the
64-example charge/discharge run back to 50\%.

This is direct evidence that the linear-readout trouble is tied to the
hardware state map.  The sign of the write can be locally sensible, but the
effective update is still
\[
  \dot w_{\mathrm{eff}}
  =
  \eta\,\delta a\,G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta),
\]
and the one-sided discharge primitive appears to keep that product better
conditioned than the charge-only or symmetric charge+discharge primitive in the
current operating range.  A short width sweep reinforces that interpretation:
on the same 64-example task, bounded discharge with a smaller
\(0.00015\,\mu\mathrm{m}\) selected-stack width reached 93.75\%, and
\(0.00035\,\mu\mathrm{m}\) reached 95.3125\%.  We should therefore treat the
linear-readout bug as a state-dependent mobility problem first, and only then
scale the representation or depth.

The first 128-example fixed8 readout scale probe confirms that this is not
fully solved yet.  With the same \(0.70/0.24\ \mathrm{V}\) bounded-discharge
rails, \(0.00035\,\mu\mathrm{m}\) reached 83.59375\%, while the weaker
\(0.00015\,\mu\mathrm{m}\) setting fell to 60.15625\%, and a
\(0.0005\,\mu\mathrm{m}\) setting again reached only 83.59375\%.  A stronger
two-epoch \(0.0008\,\mu\mathrm{m}\) setting improved the same 128-example
subset to 85.9375\%, while \(0.0012\,\mu\mathrm{m}\) slipped to 85.15625\% with
a worse final margin.  Repeating \(0.0008\,\mu\mathrm{m}\) for four epochs also
regressed to 83.59375\%.  So \(0.0008\,\mu\mathrm{m}\) for two epochs remains
the best 128-example readout-only point, but it still does not clear 90\%.
The initial and final hidden feature diagnostics still find a linear separator,
so the remaining readout issue is still a hardware update-field problem rather
than a reason to immediately complicate preprocessing.

A direct read/write mobility sweep explains the 128-example stall more sharply.
The old shared \(0.70/0.24\ \mathrm{V}\) bounded-discharge window leaves the
negative read branch saturated over the entire operating band.  In the
\code{device\_readout\_mobility\_v1} sweep, the estimated signed mobility for a
desired positive effective-weight update was essentially zero at
\(\theta=0.24,0.34,0.46,0.58,0.70\ \mathrm{V}\), while the desired negative
update still had nonzero mobility through the positive branch.  This means the
readout can reduce effective weights but often cannot increase them in the
state range where the random readout was initialized.  Moving the negative
branch into its measured high-slope range fixes the sign alignment in the
cell-level sweep: \code{device\_readout\_mobility\_v12} used a
\(0.16/0.10\ \mathrm{V}\) bounded-discharge range and showed nonzero
increase/decrease mobility throughout that narrower band.  The generator
therefore now supports branch-specific readout initialization centers and
branch-specific bounded write rails.  This is not a new algorithm; it is a
hardware-state-map correction so that the same local error/pre trace can move
both signs of the effective readout weight.

A stricter two-dimensional branch-pair mobility analysis now combines a
positive-branch sweep and a negative-branch sweep without forcing the two
branches to share the same \(\theta\).  The
branch-pair table combining the \(v1\) positive sweep with the \(v12\) negative
sweep is sign-aligned over the tested \(0.24\)--\(0.70\ \mathrm{V}\) positive
window and \(0.10\)--\(0.16\ \mathrm{V}\) negative window.  Its best-balanced
representative pair is near
\((\theta^+,\theta^-)=(0.24,0.10)\ \mathrm{V}\), with nearly equal positive
and negative signed-update mobility but very small mobility.  The
\((0.46,0.16)\ \mathrm{V}\) pair has stronger mobility but only a small
signed read gain, so it needs score-path calibration in addition to write-path
calibration.

The branch-pair summary now also reports a gain-safe operating pair across the
whole activation sweep, rather than only the mobility-balanced pair at a single
representative activation.  This matters because the backward/update mobility
depends on \(G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)\), while the
forward and reverse error-flow sign depends on \(G_{\mathrm{eff}}(\theta)\).
The old \((0.46,0.16)\ \mathrm{V}\) candidate is sign-aligned in mobility, but
its signed read gain flips sign at low activity in the measured table.  The
stricter summary selects \((0.46,0.10)\ \mathrm{V}\) as the best gain-safe
branch pair over the current sweep: its minimum measured signed read gain is
positive, although its worst-case mobility balance is much poorer than the
\((0.24,0.10)\ \mathrm{V}\) pair.  That gives a concrete circuit-level
hypothesis for the linear-readout failures: the cell can move in the locally
correct state direction while presenting the wrong or too-small effective
conductance to low-activation samples.

The branch-pair analysis now separates two parameterizations of the same
physical state.  The raw hardware-update columns estimate
\(G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)\), while the new
physical-state-gradient columns estimate what would happen if the local write
current gained an additional \(G'_{\mathrm{eff}}(\theta)\) factor.  Re-analyzing
the \(v1\) positive and \(v12\) negative sweeps with these columns shows why
this distinction matters.  At the representative activation, the best raw
mobility-balanced pair remains \((0.24,0.10)\ \mathrm{V}\), with raw balance
0.994, but its physical-gradient balance is only 0.418.  The best gain-safe
pair, \((0.46,0.10)\ \mathrm{V}\), is worse: raw worst-case mobility balance is
0.080 and physical-gradient worst-case balance is only 0.0037.  So a naive
``multiply the write by \(G'\)'' correction is not automatically better for the
current cell.  It can amplify the branch-slope asymmetry unless the operating
window is chosen for both \(G_{\mathrm{eff}}\) and \(G'_{\mathrm{eff}}\).

The first branch-pair training probes confirm that distinction.  On
\code{mnist01fixed8\_64}, \((0.24,0.10)\ \mathrm{V}\) stayed at 50\% with a
74.2\% target-mistake gate match, while \((0.70,0.10)\ \mathrm{V}\) inverted
the score lead and produced a 0\% target-mistake match.  The
\((0.46,0.16)\ \mathrm{V}\) pair had a good 90.6\% gate match, but only
56.25\% final accuracy at \(0.00025\,\mu\mathrm{m}\).  Adding independent
forward-read branch-width controls gave more information: halving the negative
forward read width improved the gate match to 96.1\% but still collapsed to
50\%, while increasing the positive forward read width by \(1.5\times\) reached
76.5625\%.  So branch-specific storage fixes a real
\(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) problem locally, but the useful circuit
still needs a joint score-common-mode/read-gain calibration.  The old shared
\(0.70/0.24\ \mathrm{V}\) bounded-discharge window remains the best 64-example
readout result despite its one-sided mobility defect.

A more direct error-node diagnostic narrows the failure.  With the
\((0.34,0.10)\ \mathrm{V}\) branch pair, interleaved examples, and
bounded-discharge writes, the target-mistake backward gate was correct on the
training rows, and the error rails had the expected signs.  For class-0 rows,
for example, the measured output error was approximately
\(\delta_0=+1.043\) and \(\delta_1=-1.043\).  Nevertheless the accumulated
signed readout state changes were negative for both output heads, and the
classifier collapsed to class 1.  The physical reason is that the negative
branch was initialized at its bounded-discharge low rail, \(0.10\ \mathrm{V}\).
For an update that should increase a signed weight by lowering the negative
branch, the intended write path is already saturated.  Small inactive-side
leakage can still lower the positive branch, so the effective signed weight can
move opposite the useful direction even though the error signal itself is
correct.

Branch-specific write widths do not fix that rail-pinning failure, because a
wider transistor cannot discharge a capacitor below its selected low rail.  In
\code{v401} and \code{v402}, increasing the negative-branch write width from
\(0.0008\,\mu\mathrm{m}\) to \(0.0024\) and \(0.0032\,\mu\mathrm{m}\) still
left the 64-example readout at 50\%.  Switching to
\code{bounded\_charge\_discharge} opened the missing target-increase path, but
then the collapse flipped to class 0 at write widths
\(0.0002\)--\(0.0008\,\mu\mathrm{m}\).  That is the current best evidence that
the linear-model blocker is a hardware write-kernel balance problem, not a
Python-side gradient-computation problem: the circuit needs a branch/action
write primitive whose induced mobility is sign-aligned and not rail-pinned
over the operating window.

The first reduced write primitive is \code{bounded\_charge\_only}: instead of
both charging the desired branch and discharging the opposite branch, the
backward window only charges the branch that should make the signed weight move
in the selected direction.  On the same 64-example fixed8 readout, a
\(0.00035\,\mu\mathrm{m}\) charge-only width still collapsed to class 0, but
\(0.0008\,\mu\mathrm{m}\) reached 75\% final accuracy.  Increasing the same
charge-only width further was not monotone: \(0.0012\,\mu\mathrm{m}\) fell back
to 53.125\%, while \(0.0016\,\mu\mathrm{m}\) reached 71.875\%.  Separately,
starting the negative branch above its low rail, at \(0.13\ \mathrm{V}\), did
not rescue bounded-discharge training; both \((0.34,0.13)\ \mathrm{V}\) and
\((0.46,0.13)\ \mathrm{V}\) stayed at 50\%.  This is not yet a good readout
learner, but it is a useful sanity check: removing the over-aggressive
discharge component improves the one-layer circuit without adding any Python
gradient computation, and the remaining nonmonotonicity is exactly what the
hardware-mobility view predicts.

Two branch-width probes tested whether the charge-only result was simply
over-charging the negative branch.  Keeping the positive branch at
\(0.0008\,\mu\mathrm{m}\) and reducing the negative branch to
\(0.0004\,\mu\mathrm{m}\) reached only 53.125\%; reducing it further to
\(0.0002\,\mu\mathrm{m}\) collapsed to 50\%.  The first probe did reduce the
output-1 signed-state drift from about \(-0.97\,\mathrm{V}\) in the
state-high center-pull run to \(-0.52\,\mathrm{V}\), but the
target-mistake backward-gate match fell to 49.2\%.  The second probe made the
gate worse still, with only 20.3\% match.  Thus static branch-width scaling can
change the state trajectory, but it does not preserve the error-gating
contract.  The next useful write primitive should be conditional on update
direction and local state, rather than a single fixed positive/negative branch
width.

The generator now exposes action-specific readout widths:
\code{--readout-charge-update-width-u} and
\code{--readout-discharge-update-width-u}.  This separates a charge path that
raises the selected branch from a discharge path that lowers the opposite
branch, while preserving the older positive/negative branch-width controls for
single-action runs.  The first focused 64-example probes show that simply
adding back a weak discharge path is not enough.  With charge fixed at
\(0.0008\,\mu\mathrm{m}\), discharge widths of \(0.0001\),
\(0.0002\), and \(0.0004\,\mu\mathrm{m}\) all collapsed to 50\% final
accuracy; the output-1 readout row moved by roughly
\(-0.98\) to \(-1.02\,\mathrm{V}\) in total signed state, far more than the
output-0 row.  Increasing charge to \(0.0012\,\mu\mathrm{m}\) with
\(0.0001\,\mu\mathrm{m}\) discharge recovered only 64.0625\%.  Thus the
charge-only result is not just missing a little opposite-branch cleanup; the
two-action write primitive is still badly row/asymmetry conditioned.

The next density-preserving correction is a branch-specific center-pull path.
The previous optional center pull used one rail for both branches, which is a
poor match for the measured mobility windows: the positive branch has useful
read slope in a much higher voltage range than the negative branch.  The
generator now has independent weak transistor pulls to
\code{wcenterp}/\code{wcentern} for readout weights and
\code{wbocenterp}/\code{wbocentern} for output-bias weights.  This is not a
Python regularizer; it is a local MOS state path active during the
backward/write window.  The pull can be gated either by the analog
\code{bwd} rail or by the later scheduled \code{apply} waveform; the latter is
useful when the extra center-pull gates load or capacitively disturb the
self-timed mistake rail.  Its intended role is to keep
\(\theta^+\) and \(\theta^-\) near their own measured
\(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) operating regions while the normal
pre/error-gated write stack supplies the signed update.

The first center-pull probes are useful negative controls.  Re-running the
\((0.34,0.10)\ \mathrm{V}\) branch-pair charge-only readout with a
\(2\,\mathrm{fF}\) mistake-rail capacitor reproduced the earlier 75\% result
on \code{mnist01fixed8\_64}; the same setup with a \(0.5\,\mathrm{fF}\)
mistake-rail capacitor reached only 59.375\%, so the analog \code{bwd} rail
capacitance is part of the learning primitive.  Adding a
\(0.00002\,\mu\mathrm{m}\) branch-specific center pull gated directly by
\code{bwd} dropped the cap-\(2\,\mathrm{fF}\) run to 53.125\%, with the
backward rail opening on 96 of 128 training cycles.  Moving the center pull to
the later \code{apply} waveform avoids direct loading of \code{bwd}, but did
not improve accuracy: \(0.00002\,\mu\mathrm{m}\) reached 54.6875\%, and
\(0.000005\,\mu\mathrm{m}\) reached 67.1875\%.  The conclusion is that
branch-centering is now expressible as hardware, but this simple always-on
weak pull fights the signed update more than it helps.  The next write-kernel
work should make centering conditional or state-windowed, rather than applying
a uniform pull on every training example.

A state-windowed center-pull variant was then added as a more local version of
the same idea.  In \code{state\_high} mode, the center path is a two-device
stack: the global write or backward rail first gates an intermediate node, and
the stored weight capacitor itself gates the final path to its branch-specific
center rail.  Thus the weak pull is only strong when the state is already high
enough to turn on the second device.  This is closer to a MOS mobility-window
mechanism than the always-on pull, but it was still a negative control on the
64-example fixed8 task.  With the same \((0.34,0.10)\ \mathrm{V}\) branch
centers, charge-only write, \(2\,\mathrm{fF}\) mistake rail, and \code{apply}
gating, \code{0.00002u} state-high center pull reached 57.8125\%, and
\code{0.00008u} collapsed to 50\%.  The measured output-row movement was still
badly asymmetric, with output 1 moving by about \(-0.97\) to
\(-1.01\,\mathrm{V}\) in signed state.  So the failure is not just that the
old center pull was unconditional; a useful fix likely has to be
write-direction-aware or explicitly mobility-aware, not merely state-high
clamping.

The same \(G_{\mathrm{eff}}\) versus \(G'_{\mathrm{eff}}\) distinction also
suggests a better place to put the state dependence: inside the selected write
stack itself, not as a separate pull applied after the fact.  The generator now
has a \code{readout\_write\_state\_gate\_mode} control.  In
\code{state\_high\_discharge} mode, a discharge path must first pass through an
NMOS gated by the stored branch capacitor, so a branch that is already near its
low rail has much less discharge mobility.  In \code{state\_window} mode, the
charge path also passes through a PMOS gated by the stored branch capacitor, so
charging naturally weakens as the branch approaches the high rail.  This does
not make the chip compute \(G'_{\mathrm{eff}}\) explicitly.  It implements a
more plausible hardware mobility factor \(s_{\mathrm{MOS}}(\theta)\), chosen so
the induced effective-weight mobility
\[
  G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)
\]
vanishes near the rails instead of letting inactive leakage dominate a pinned
selected branch.  If the 64-example linear readout improves under this mode,
that is evidence that the failure was a physical-state mobility problem; if it
does not, the next suspect is the event/error gate or the forward read
common-mode calibration.

The first two state-gated write probes were negative controls, but useful
ones.  On the 64-example fixed8 readout with \((0.34,0.10)\ \mathrm{V}\)
branch centers and a perfect target-mistake gate, \code{state\_window} plus
\code{bounded\_charge\_discharge} stayed at 50\% final accuracy.  The signed
readout movement was still negative for both output heads
\((-0.755,-0.744)\ \mathrm{V}\).  The \code{state\_high\_discharge} plus
\code{bounded\_discharge} run also stayed at 50\%, with total output-row
movements \((-1.093,-0.899)\ \mathrm{V}\).  Thus the self-gated write stack is
not enough by itself.  It did reduce or reshape the total movement, but it did
not solve the selected-action balance problem.  The current interpretation is
that the \(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) diagnosis is still right, but
the write primitive needs action-specific mobility characterization rather than
only a generic state-high or state-window gate.

The mobility sweep now has that direct action-specific diagnostic.  Instead of
inferring the signed update only from separate single-branch slopes, it can
instantiate a two-branch signed readout cell, read its effective signed
response, apply one requested signed write action, and read the effective
response again.  This gives the finite hardware quantity
\[
  \Delta r_{\mathrm{signed}}
  =
  r_{\mathrm{after}}^{+}-r_{\mathrm{after}}^{-}
  -
  \left(r_{\mathrm{before}}^{+}-r_{\mathrm{before}}^{-}\right),
\]
and then checks whether it is positive for a requested signed increase and
negative for a requested signed decrease.  On the branch grid
\(\theta^+\in\{0.24,0.34,0.46,0.58\}\) and
\(\theta^-\in\{0.10,0.13,0.16,0.24\}\), the baseline
\code{bounded\_charge\_discharge} write at \(0.0008\,\mu\mathrm{m}\) is
sign-aligned on 77.1\% of the sampled action cases.  Its best sampled pair is
\((\theta^+,\theta^-)=(0.34,0.13)\ \mathrm{V}\), with all sampled
increase/decrease actions aligned and a minimum desired signed-read movement of
about \(0.00093\,\mathrm{V}\).  The \code{state\_window} version is worse:
only 50\% of actions are aligned, and all measured signed-read deltas are
non-positive, so it can effectively move the separator in only one direction.
This explains the failed \code{state\_window} training run and gives a concrete
next probe: use the baseline two-action write, but initialize the negative
branch around \(0.13\,\mathrm{V}\) rather than pinning it at the low rail.

Running that probe on the 64-example fixed8 readout confirmed that the
derivative/mobility diagnosis is necessary but not sufficient.  With
\((\theta^+,\theta^-)=(0.34,0.13)\,\mathrm{V}\), the old source-follower
output head and raw score sense amp still failed: \code{v448} reached only
51.56\%, and its lead gate tracked the score winner on only 49.2\% of training
cycles.  Halving the write width in \code{v449} made the event path even worse,
ending at 50\%.  Replacing the output head with the common-mode-rejecting
\code{score\_diff} head and using \code{out\_senseamp} in \code{v450} improved
the lead-gate winner match to 96.1\% and raised final accuracy to 62.5\%, but
the target-mistake gate was still only 83.6\% separable at its best threshold.
So the \((0.34,0.13)\,\mathrm{V}\) branch pair has better local pair-action
mobility, but the full training loop also needs a calibrated event circuit.

A follow-up split the event problem from the local write-field problem.
\code{v451} latched the target-mistake event before replaying the backward
window.  It reached 64.06\%, the best point in this small batch, and the latch
signal contained good information: the best-threshold match was 97.7\%.
However, at the fixed \(0.5\,\mathrm{V}\) replay threshold it opened 118 of 128
cycles, giving many false positives.  \code{v452} instead used
output-conditioned competitive error rails.  Its event gate was almost perfect
\((99.2\%\) match, one false positive), but final accuracy fell back to 50\%
and both output rows moved negative by about \(-0.76\,\mathrm{V}\).  That
run is especially useful: once the event gate is nearly correct, the remaining
failure is the induced effective write field, i.e. the realised
\(G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)\) under the selected
\(\mathrm{dp}/\mathrm{dn}\) rails.

The new actual-rail action probe makes this more concrete.  At the
\((\theta^+,\theta^-)=(0.34,0.13)\ \mathrm{V}\) readout point, the ideal
pair-action write remains sign-aligned when the write pre-gate is high
(\(0.65\) to \(0.75\ \mathrm{V}\)), but falls to only 50\% sign alignment when
the pre-gate is \(0.25\) or \(0.50\ \mathrm{V}\).  The full-swing
\code{perceptron} error rails therefore still fail for low and middle
activations, while the \code{out\_competitive} rails are also much too weak:
they reach only about \(48\ \mathrm{mV}\) on the selected \(\mathrm{dp}/
\mathrm{dn}\) rail in the probe.  Across twelve actual-rail action cases,
only two moved both output rows in the desired signed direction.  So the
linear-readout blocker is directly related to the
\(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\) issue, but the immediate circuit symptom
is even more specific: the write stack needs a sign-aligned mobility region for
ordinary activation voltages, not only for an artificially boosted pre gate.

The new \code{synapse\_boost} path tests that hypothesis inside the actual
netlist style.  A MOS store transistor charges a local pre-trace capacitor during
the forward window, then a small capacitive bootstrap from the \code{preboost}
guide rail raises that stored gate only during the backward/write window.  In the
actual-rail action probe at
\((\theta^+,\theta^-)=(0.34,0.13)\,\mathrm{V}\), a \(0.75\,\mathrm{V}\)
bootstrap remained too weak: only \(1/6\) perceptron action cases moved both
rows correctly.  Raising the bootstrap to \(1.0\,\mathrm{V}\) improved the
perceptron action probe to \(4/6\), and \(1.2\,\mathrm{V}\) reached \(6/6\) with
a minimum desired signed-read movement of about \(1.46\,\mathrm{mV}\).  Sweeping
the error rule at the same \(1.2\,\mathrm{V}\) setting showed that
\code{perceptron} and \code{out\_residual} are locally sign-aligned, while
\code{competitive} and \code{margin} still move at least one row the wrong way.
This is the clearest direct evidence so far that the linear readout trouble was
partly a pre-gate/write-mobility problem, not only a feature-separability
problem.

The full training loop is not solved yet.  On \code{mnist01fixed8\_16}, scheduled
\code{perceptron} with the \(1.2\,\mathrm{V}\) bootstrapped pre-gate improved from
37.5\% initial accuracy to 68.75\%, and the same setting on
\code{mnist01fixed8\_64} improved from 40.625\% to 79.6875\%.  Reducing the write
width to \(0.0002\,\mu\mathrm{m}\) fell back to 50\%, and the scheduled
\code{out\_residual} version also fell to 50\% while both output rows moved
negative.  Adding the analog \code{target\_mistake} backward gate gave a useful
gate signal (92.1875\% match, no false positives, five false negatives) but only
62.5\% final accuracy.  The updated diagnosis is therefore: the boosted
pre-gate fixes the local action sign for some error rules, but the training
system still needs a selective full-swing event/error circuit and better
step-size control before the linearly separable readout consistently converges.

Mistake-latch gates do not yet fix the 64-example readout either.  Replacing
the continuous target-mistake backward gate with
\code{target\_mistake\_latch\_simple} at charge-only widths
\(0.0008\) and \(0.0016\,\mu\mathrm{m}\), and with the fuller
\code{target\_mistake\_latch} at \(0.0008\,\mu\mathrm{m}\), all stayed at
50\% final accuracy.  The reason is visible in the instrumentation: the latch
open count was zero at the fixed \(0.5\ \mathrm{V}\) threshold, even though the
best-threshold match fraction was 75.8--81.25\%.  The latch signal therefore
contains useful analog information, but its current gain/threshold is badly
sized for this low-voltage branch-pair operating point.

The next latch variant sampled the output capacitors directly during the error
window.  This made the event variable itself much cleaner:
\code{target\_out\_mistake\_latch} had a best-threshold match fraction of
100\% on the 64-example fixed8 run.  However, the stored event topped out near
\(0.21\,\mathrm{V}\), so it still could not directly open the backward rail at
the fixed \(0.5\,\mathrm{V}\) threshold and final accuracy remained 50\%.  A
restored version then added a dynamic inverter and PMOS pull-up to regenerate a
full backward rail from the low-voltage event capacitor.  That circuit proved
the rail-strength problem is solvable: the backward rail reached about
\(1.15\,\mathrm{V}\).  It also over-opened on every training cycle, producing
57 false positive mistake windows and only 57.8125\% final accuracy.  The
remaining event-circuit problem is therefore discriminator selectivity, not
rail strength.  In the language above, this is the error-gate side of the same
hardware-defined learning rule: even if \(G'_{\mathrm{eff}}s_{\mathrm{MOS}}\)
is usable, a nonselective backward gate changes which examples receive the
update and can still prevent a linearly separable readout from converging.

Two follow-up restored-latch probes tested whether a higher effective event
threshold would fix the over-open behavior.  A two-device NREL restore stack
(\code{target\_out\_mistake\_latch\_restore\_stacked}) at widths 256 and
\(64\,\mu\mathrm{m}\) still reached only 57.8125\% final accuracy.  The
width-256 run opened the backward rail on all 128 training cycles; the
width-64 run reduced this to 127 openings and 55 false positives, but still
did not create a usable mistake gate.  A timed version that gated the restore
stack with \code{bwd\_src} also opened on all cycles at both widths.  The new
\code{merr\_bar} instrumentation showed that the inverter can swing, but not
selectively enough: the minimum restored-bar voltage fell nearly to ground and
the mean was about \(0.51\,\mathrm{V}\), while the backward rail stayed near
full supply.  The event capacitor values themselves are separated by only
millivolts once the always-open write path perturbs the readout, so the next
event-circuit attempt should use a real full-swing comparator/sense latch or
the existing full-rail lead signals, not another raw threshold on the
\code{merr} capacitor.

The first such lead-signal event circuit now exists.  The
\code{lead\_mistake} error rule uses the full-swing output-winner rails, with
an explicit lead-mode convention, to open \(\mathrm{dp}\) for a target row that
is currently losing and \(\mathrm{dn}\) for a non-target row that is currently
winning.  On \code{mnist01fixed8\_16} with the \(1.2\,\mathrm{V}\)
bootstrapped pre-trace gate, these rails matched the desired target-loss
actions exactly: 100\% rail-action match, no false positives, no false
negatives, and full-strength output-error rails near \(1.04\,\mathrm{V}\).
However, the four-epoch run improved only from 37.5\% to 50\%, and an
eight-epoch run with twice the write width fell from 37.5\% to 43.75\%.
This is useful negative evidence.  It says the immediate failure is no longer
``Python chose the wrong event'' or ``the event rail is too weak.''  The
remaining readout problem is the induced write field: the selected
\(\mathrm{dp}/\mathrm{dn}\) rails, pre-trace boost, branch voltages, and MOS
stacks still have to produce a sign-aligned and well-scaled
\(G'_{\mathrm{eff}}(\theta)s_{\mathrm{MOS}}(\theta)\) update over the actual
training trajectory.

The actual-rail mobility probe now covers this lead-driven case directly.  With
\code{lead\_mistake}, \code{out\_senseamp} lead polarity, the
\(1.2\,\mathrm{V}\) bootstrapped pre-trace gate, and the
\((\theta^+,\theta^-) \approx (0.34,0.13)\,\mathrm{V}\) branch point, all 24
probed label/action cases were sign-aligned.  The rail generation and write
polarity are therefore correct at the local-cell level.  The limiting detail is
scale: for very small activations, the desired signed-read movement was only
about \(10^{-8}\), while ordinary \(0.5\) to \(0.75\) activations moved by a few
millivolts in signed read response.  This is consistent with a
state-dependent mobility problem rather than a simple sign bug.

Changing the training order exposed a second online-learning effect.  The
original runs used the dataset order, all zeros followed by all ones, so the
last support-vector update in each epoch was always a class-1 update.  An
interleaved order removes that artifact but does not solve the circuit: at
width \(0.0016\,\mu\mathrm{m}\), accuracy stayed at 37.5\% and every training
cycle opened a lead-mistake update.  Reducing the width to
\(0.0008\,\mu\mathrm{m}\) improved the same interleaved run to 62.5\%, but
still opened 114 target-loss updates out of 128 cycles and the lead latch only
tracked the score winner 82.8\% of the time.  The next knobs are therefore
smaller write pulses and a stronger or cleaner winner-sense path, not a larger
dataset.

The state-dependent write gates need to be checked at the actual action level,
not only in the branch-only mobility table.  A new grouped-by-activation
summary makes this visible.  With no state gate, \code{lead\_mistake} remains
sign-aligned for all 24 probed action cases, but the minimum desired signed
movement is only \(1.3\cdot10^{-8}\) at \(a=0.08\), compared with
\(2.37\,\mathrm{mV}\) or more at \(a=0.5\).  This is the clearest
low-activation starvation measurement so far.

\code{state\_window} is not a safe fix in this topology.  Its branch-only
signed mobility is positive, but the full actual-rail \code{lead\_mistake}
probe has 0/24 both-row sign alignment.  The extra state devices interact with
the real \(\mathrm{dp}/\mathrm{dn}\), pre-trace, and charge/discharge stacks
enough to change the selected update action.  \code{state\_high\_discharge} is
less destructive: it keeps 24/24 action signs correct, but it suppresses the
action-level movement severely.  At \(a=0.5\), the minimum desired signed
movement falls from \(2.37\,\mathrm{mV}\) without the gate to only
\(29.4\,\mu\mathrm{V}\).  So the next useful mobility control should not be the
current full \code{state\_window} stack.  Better candidates are smaller ordinary
write pulses, asymmetric branch widths, or a gentler state-dependent write path
whose action-level sign and magnitude are characterized before training.

The matched training runs agree with that action-level diagnosis.  On the
16-sample interleaved fixed8 readout, \code{state\_window} reached only 50\%
even though its lead rails matched the desired mistake events perfectly; the
total row-0 signed readout motion was negative, consistent with the failed
action probe.  The plain no-state-gate run at \(0.0004\,\mu\mathrm{m}\) reached
68.75\%, slightly better than the previous \(0.0008\,\mu\mathrm{m}\) no-gate
run but still with negative final margin.  \code{state\_high\_discharge} at
\(0.0008\,\mu\mathrm{m}\) reached 75\%, the best result in this lead-mistake
interleaved readout family so far, although its lead winner tracking was only
78.9\%.  That makes \code{state\_high\_discharge} a useful current direction,
but not yet a solved readout trainer.  The immediate follow-ups are stronger
lead sensing and lower \code{state\_high\_discharge} pulse width.

Those follow-ups reject the simplest lead-strength explanation.  Raising the
lead sense width from \(96\) to \(256\,\mu\mathrm{m}\) improved the score-winner
tracking only slightly, from 78.9\% to 80.5\%, but final accuracy fell from
75\% to 56.25\%.  Lowering the \code{state\_high\_discharge} pulse width to
\(0.0004\,\mu\mathrm{m}\) kept final accuracy at 75\% and improved the final
margin from \(-11.7\) to \(-6.7\,\mathrm{mV}\).  So the current best
lead-mistake readout setting is the gentler \code{state\_high\_discharge}
write, not a stronger lead latch.  The next experiments should sweep still
smaller pulses and longer training windows before scaling the dataset.

The first of those sweeps shows a narrow useful pulse range.  Halving the
\code{state\_high\_discharge} pulse again to \(0.0002\,\mu\mathrm{m}\) reduced
the total signed readout motion and fell back to 50\% final accuracy.  Keeping
\(0.0004\,\mu\mathrm{m}\) but extending training from 8 to 12 epochs also fell
back to 50\%, with all digit-1 samples wrong at the final evaluation.  This
looks like transient useful learning followed by overshoot or class-drift, not
a monotone convergent readout optimizer.  A self-timed stop rule, per-example
margin-sensitive update suppression, or a less binary mistake rail may be more
important than simply changing the global pulse width.

The generator also mirrors the write-mode choice on the lower-layer synapses.
The corresponding option is
\code{--hidden-flow-}\allowbreak\code{write-mode}.  When hidden direct flow is enabled, hidden
synapse capacitors can use the same discharge-only, charge-only,
charge/discharge, and bounded variants as the readout.  This gives the
all-layer backprop path the same bounded-write and state-gating knobs as the
readout, although the action-level probes above show that the current full
\code{state\_window} stack is not a safe default.

The first bounded-hidden-write all-layer check is positive.  On
\code{mnist01fixed8\_32}, with per-synapse pre-activation trace gates,
readout-weight-transport hidden deltas, bounded-discharge readout writes, and
bounded-discharge hidden writes, the circuit reached 100\% final accuracy with
a small positive final transient margin.  The hidden signed-weight capacitors
moved by about \(21\ \mathrm{mV}\), so this is not a readout-only artifact.
Scaling the same bounded-hidden-write configuration to 64 examples reached
92.1875\% with about \(26.7\ \mathrm{mV}\) of hidden signed-weight motion.  That
64-example run does not beat the best readout-only accuracy, but it confirms
that the newly bounded lower-layer write path is usable at the next scale and
does not collapse the trained readout.  Scaling that exact all-layer
configuration to 128 examples failed, however: the run reached only 70.3125\%
while moving hidden signed-weight capacitors by about \(55.5\ \mathrm{mV}\).
The target-mistake gate match fell to 73.8\%, so the larger all-layer failure
looks like a hidden-delta/event-quality problem coupled to mobility, not a lack
of hidden-weight motion.

A broader replay sweep clarified why the recent accuracy appeared to drop.  The
old high-scoring 40-example bridge still reproduces under the current generator:
\code{v481}, the readout-only out-competitive target-mistake run, reaches
97.5\%, and \code{v480}, the per-synapse pre-trace hidden-write version, also
reaches 97.5\% while moving hidden signed-weight capacitors by about
\(9.46\,\mathrm{mV}\).  So the old result was not lost.  It was a friendlier
40-example bridge with a strong out-competitive readout update, not the newer
strict lead-mistake/branch-pair circuit.  Scaling that same out-competitive
readout-only recipe to 64 examples in \code{v483} reaches 84.375\%, which is
useful but below the 90\% target.

The soft lead-mistake variants are useful negative results.  Adding a
\code{lose[target]} NMOS in series with the lead-mistake rail
\(\left(\code{lead\_mistake\_lowtarget}\right)\) starved the rail in the
actual-action probe: all 24 action cases failed, with essentially zero
\(\mathrm{dp}/\mathrm{dn}\) drive.  Replacing that with an analog PMOS
output-low source gate
\(\left(\code{lead\_mistake\_outlow}\right)\) fixed the local action signs:
both the plain and state-high variants were 24/24 sign-aligned in the
actual-rail probe.  But training did not improve.  On the 16-example
interleaved fixed8 readout, \code{v477} reached 68.75\%, \code{v478} reached
75\%, and the identity-feature plus output-bias run \code{v484} also reached
75\%.  The lesson is practical: locally correct rail polarity is necessary, but
the lead-mistake family is not yet the best training rule.

The better current direction came from replaying past winners rather than
tightening the new lead-mistake design.  The old 64-example bounded-discharge
\code{senseamp\_strong} replay \code{v485} reached only 60.9375\% under the
current generator because the target-mistake gate matched poorly.  Changing
only the lead source to \code{out\_senseamp} recovered the useful behavior:
\code{v487} reached 90.625\% on \code{mnist01fixed8\_64}, and extending the
same setting to four epochs in \code{v492} reached 93.75\%.  Reducing the
write width to \(0.00025\,\mu\mathrm{m}\) in \code{v493} stayed at 90.625\%.
Nearby controls failed: raw \code{score} lead stayed at 50\%, scheduled gating
stayed at 50\%, \code{lead\_or} reached only 51.5625\%, and the
\code{out\_residual} scheduled run stayed at 50\%.  Thus the best stable
readout-only recipe is now:
\[
  \code{source\_follower}
  + \code{out\_senseamp}
  + \code{target\_mistake}
  + \code{bounded\_discharge}.
\]

The hidden-write version of that recipe is not yet stable.  Two 64-example
full-hidden replays with bounded hidden writes, \code{v486} and \code{v494},
hit ngspice timestep failures in hidden-delta/write-stack nodes.  This should
be treated as a separate circuit robustness task, not as evidence against the
readout recipe.  A smaller stabilization attempt with a \(0.0000002\,\mu
\mathrm{m}\) bounded hidden-write stack, \code{v499}, also failed with an
ngspice timestep collapse at a hidden-delta node, so this is still a numerical
and circuit-conditioning issue.

The follow-up sweep around the \code{v492} recipe gives a clearer empirical
direction.  Scaling the same readout-only recipe to \code{mnist01fixed8\_128}
for two epochs in \code{v495} reached 92.96875\%, even though the raw eight
fixed8 input features for that 128-example subset were not linearly separable.
Scaling further to \code{mnist01fixed8\_256} for two epochs in \code{v500}
reached 96.09375\%, the best dense device-level fixed8 result so far.  The same
recipe is not a steady-state classifier, however.  A four-epoch 128-example run
\code{v501} fell to 90.625\%.  Adding explicit no-write checkpoint evaluations
in \code{v515} showed the transient optimum directly: 91.40625\% after epoch 1,
92.96875\% after epoch 2, 89.84375\% after epoch 3, and 89.0625\% after epoch 4.
An interleaved-order checkpoint run, \code{v516}, also peaked around epoch 2
(92.1875\%) but collapsed to 75\% by epoch 4, so interleaving is not a cure for
the drift in the current circuit.  The checkpoint cycles themselves add extra
read/eval exposure, so their final number should be compared cautiously with
non-checkpoint runs, but they confirm that the useful region is transient.

Several broad controls also narrowed the design space.  The old high-width
\code{out\_competitive} discharge recipe did not scale: \code{v505} and
\code{v506} stayed at 50\% on 64 examples, and \code{v507} reached only
69.53125\% on 128 examples.  Combining \code{out\_competitive} with the newer
bounded-discharge write in \code{v508} also stayed at 50\%.  The two new
lead-mistake variants, \code{v509} and \code{v510}, each reached 92.1875\% on 64
examples, below the \code{v492} 93.75\% baseline.  The pass-activation readout
synapse \code{v511} fell to 42.1875\%.  Sampling the 64-example four-epoch run
at several output times in \code{v497} gave the same 93.75\% accuracy at 2.55,
2.75, 2.95, 3.15, and 3.35 ns, so this particular recipe is not fragile to the
exact readout-sampling instant.  Adding small random readout charge pulses in
\code{v496} reduced the result to 92.1875\%, and enabling a small trained
output-bias write in \code{v498} also reduced it to 92.1875\%.

Hidden writes are now numerically better conditioned but still not useful at
scale.  Stabilized 32-example runs with hidden writes enabled, \code{v503} and
\code{v504}, both reached 96.875\%.  Scaling the same stabilized hidden-write
recipe to 64 examples in \code{v512} reached 90.625\%, below the readout-only
baseline.  True weighted-ReLU hidden-layer training remains unsolved: the
weighted-ReLU MNIST and XOR probes \code{v513}, \code{v514}, \code{v517},
\code{v518}, and \code{v519} all stayed at 50\%, even after disabling output-bias
writes, reducing the hidden capacitance, and increasing write strength.  CSV
separator diagnostics \code{v520}--\code{v523} also stayed at 50\%, even though
some hidden states were linearly separable in the measured CSV.  That points to
a hidden/readout interface problem in the weighted-ReLU path, not merely an
insufficient number of training iterations.

A cleanup replay separated two effects that had been conflated in the old
result tables.  The current readout-only anchor still works when it uses the
default bounded-discharge rails: \code{v551} reached 92.1875\% best accuracy on
\code{mnist01fixed8\_64}, and \code{v552} reached 93.75\% best and 91.40625\%
final accuracy on \code{mnist01fixed8\_128}.  Replaying the same idea with
explicit \(0.70/0.24\) write rails in \code{v545} reached only 76.5625\% best
and 65.625\% final accuracy, so the rail window itself is an active circuit
parameter rather than a harmless notation change.  The full-hidden replay
\code{v550} again failed at a hidden-delta internal node, but adding explicit
hidden-delta parasitic damping in \code{v555}
\[
  C_{\mathrm{hd,int}}=0.02\,\mathrm{fF}, \qquad
  R_{\mathrm{hd,int}}=1\,\mathrm{G}\Omega
\]
made the 64-example full-hidden run complete at 90.625\% accuracy, with hidden
weight capacitors moving by 13.8 mV.  That makes the hidden-delta capacitance
and leakage a required stabilization knob for the real hidden-write path.
Raising the damping capacitance to \(0.05\,\mathrm{fF}\) in \code{v558} still
completed and again reached 90.625\% on the 64-example subset, with hidden
weights moving 13.3 mV, but the first epoch was weaker.  Scaling the damped
full-hidden path to 128 examples in \code{v557} did not yet work: the one-epoch
run fell from 63.3\% initial accuracy to 61.7\%, even though hidden weights
moved 7.4 mV.  The current interpretation is that damping fixes the numerical
stability problem, but the hidden-write path still perturbs the 128-example
readout dynamics rather than improving them.
A direct isolation run supports that interpretation.  \code{v565} used the
same 128-example readout recipe with per-synapse pre-activation trace gates
enabled, but kept hidden writes off.  It reached 91.40625\% after two epochs,
close to the \code{v552} shared-node readout anchor.  Therefore the
per-synapse trace storage is not by itself the 128-example blocker; the problem
appears when the hidden-delta/write path is allowed to change the lower-layer
weights.

The first ten-class readout bring-up exposed a different blocker.  The new
\code{mnistfixed8\_20} subset uses ten classes with two samples per class and
eight fixed input features buffered into hidden activation capacitors.  A
software perceptron on the exact input features is linearly separable, so this
is a readout-circuit test rather than a representation test.  The first
multiclass SPICE runs, \code{v535}--\code{v543}, kept the circuit at 5\%
accuracy.  Changing bounded-discharge polarity, enabling
\code{bounded\_charge\_discharge}, or replacing \code{out\_residual} with the
existing \code{score} error rails did not fix it.  Probe measurements showed
that \code{score} mostly generated a full-swing \(\mathrm{dp}\) rail for the
target class but almost no useful \(\mathrm{dn}\) rail for competing classes,
while \code{out\_residual} generated many non-target \(\mathrm{dn}\) rails that
still did not create a separating row movement.

To make the next test more circuit-local, the generator now also drives
complement target rails \(\code{nt0},\ldots,\code{nt9}\).  A new
\code{onehot} error cell uses the ordinary target rail to open
\(\mathrm{dp}_k\) for the target class and the complement target rail to open
\(\mathrm{dn}_k\) for every non-target class:
\[
  \mathrm{dp}_k \leftarrow \mathbf{1}_{k=y},
  \qquad
  \mathrm{dn}_k \leftarrow \mathbf{1}_{k\ne y}.
\]
The target and non-target stack widths are independent, reusing
\code{--residual-target-width-u} and \code{--residual-output-width-u}.  This is
not textbook softmax or exact squared-error gradient descent; it is a
MOS-defined one-vs-rest local update.  It is useful because it removes the
analog score/output subtraction from the first multiclass readout test while
still updating the same capacitor-held readout weights through local
pre-activation and error rails.

The first \code{onehot} sweeps show that multiclass failure is not simply target
rail availability.  Runs \code{v546} and \code{v547}, with \(96/12\) and
\(96/24\) target/non-target write widths, reached 30\% transient accuracy but
fell back to 10\% final accuracy; the row-wise signed weight deltas all drifted
negative and the classifier collapsed toward a few classes.  Making the target
rail much stronger in \code{v553} worsened the result to 20\% best and 10\%
final accuracy.  Charge-only writing in \code{v554} stayed at 5\% with all rows
moving positive.  The mixed \code{bounded\_charge\_discharge} write in
\code{v556} reduced the row drift and reached 25\% final accuracy, but did not
solve the one-vs-rest balance.  The next multiclass issue is therefore row
mobility and competition in the write primitive, not fixed-feature separability.

The next one-hot balance checks sharpened this diagnosis.  Reducing the
non-target stack to \(4\,\mu\mathrm{m}\) in \code{v559} still made all ten
readout rows drift negative; it peaked at 30\% and ended at 20\%.  Making charge
devices twelve times wider than discharge devices in \code{v560} reduced the
negative drift magnitude, but every row still moved negative and accuracy
peaked at only 20\%.  A new \code{onehot\_out} error cell gates each non-target
\(\mathrm{dn}_k\) rail by that class's own output voltage, so inactive
non-target rows should be suppressed by circuit dynamics rather than by Python.
This flipped the drift sign: \code{v561} and \code{v562} both moved all rows
positive, but they still collapsed mostly to a single class and peaked at 20\%.
Increasing the output-gated non-target width to \(192\,\mu\mathrm{m}\) in
\code{v563}, or reducing the target width to \(32\,\mu\mathrm{m}\) in
\code{v564}, barely changed the result: both stayed at 20\% and moved all rows
positive.  So the ten-class blocker is not only branch width; the current
error/write topology lacks a balanced class-competition mechanism, or the
width changes are being hidden by a downstream bottleneck such as the
\(\mathrm{err}/\mathrm{bwd}\) gate or output-gated write-stack headroom.

Before returning to full ten-class MNIST, the generator now supports small
counted multiclass datasets such as \code{mnist3fixed8\_30} and
\code{mnist5fixed8\_50}.  The first three-class standard-accuracy smoke run,
\code{device\_mnist3fixed8\_30\_v601\_onehot\_e2\_std}, confirms that the
multiclass SPICE path runs end-to-end with three output rows.  It also confirms
that the present one-vs-rest write rule is not yet balanced: the fixed8 input
features are linearly separable for classes 0, 1, and 2, and the initial random
readout was already at 66.7\%, but two epochs of \code{onehot} writing reduced
final accuracy to 40\% and collapsed the prediction histogram toward class 2.
Weakening the same \code{onehot} write by \(4\times\) in \code{v602} improved
the final result to 50\%, but still reduced accuracy below the initial random
readout and kept the class-2 bias.  The output-gated \code{onehot\_out} variant
\code{v603} reached 60\% final accuracy with the same weak write, better but
still below the 66.7\% initial state.  This makes the next small-multiclass
experiments a row-competition and write-balance problem, not a reason to change
the fixed input transform.

The \code{ce\_out} cell is the first softmax-cross-entropy-inspired
multiclass primitive.  It does not compute exponentials or textbook softmax;
instead, it uses target-low and non-target-own-output MOS stacks to form a
normalized-positive-current style competition.  On
\code{device\_mnist3fixed8\_30\_v604\_ce\_out\_weak\_e2\_std} it matched the
best \code{onehot\_out} result at 60\% final accuracy, so the current benefit is
architectural cleanliness rather than solved training.  A programmed
three-row hidden-space separator control,
\code{device\_mnist3fixed8\_30\_v605\_csv\_separator\_e0}, reached only
66.7\% with the initial separator scale.  Because this run has zero training
epochs, that is a readout-expression/scaling control: before interpreting
multiclass learning failures, the score head must first express a measured
separator with adequate margin.

A scale sweep on the same programmed separator showed that simply increasing
the capacitor split does not solve this.  The original gate-stack readout gave
66.7\%, 63.3\%, 56.7\%, and 60.0\% at separator scales 1, 5, 10, and 20,
respectively, with margins becoming more negative as the scale increased.
Measured hidden activations still evaluate to 100\% under the ideal linear
separator, so this is a mismatch between the ideal row logits and the MOS
readout transfer.  A voltage-mode \code{passact} readout was also tested; it
loaded the stored activation capacitors and destroyed hidden separability.
The new \code{split\_signed\_passact\_buffered\_v1} variant inserts a
source-follower replica \(\mathrm{actbuf}_j\) so readout fan-out does not drain
\(\mathrm{act}_j\).  That preserves hidden separability, but the first scale-1
and scale-5 controls still stayed at 66.7\%.  The next readout task is
therefore not preprocessing or hidden representation; it is to characterize
and redesign the synapse/output-head transfer so a programmed separator maps to
the intended score ordering.

An isolated readout-transfer harness now makes that failure measurable without
rerunning training.  It holds the measured hidden activations on the
\(\mathrm{act}_j\) capacitors, programs the readout capacitor states from the
CSV separator, and compares ideal logits with the SPICE score trajectories.
For the original single-ended score cap, the ideal hidden-space separator is
100\% accurate, but the SPICE score rows remain only 66.7\% accurate and rows 0
and 1 are anti-correlated with their intended logits.  Sweeping readout center
voltage from \(0.35\ \mathrm{V}\) to \(0.80\ \mathrm{V}\), changing the
negative-branch width, and precharging the score cap does not remove this
pathology.  The plausible circuit reason is simple: positive and negative
terms are being integrated onto one single-ended capacitor.  Near ground the
negative branch has almost no discharge headroom; at higher common-mode the
output follower treats common-mode as class evidence.  A transfer-only
\code{split\_score\_caps} probe therefore separates the two accumulators:
\(\mathrm{scorep}_k\) integrates all positive branches,
\(\mathrm{scoren}_k\) integrates all negative branches, and the diagnostic
score is \(\mathrm{scorep}_k-\mathrm{scoren}_k\).  This makes all three row
correlations positive, reaching about 0.64, 0.74, and 0.81 at separator scale
10, but argmax accuracy is still 63.3\%.  So differential score storage fixes
the sign/headroom bug, but we still need either a calibrated differential
output/error head or a readout training rule that learns the hardware-distorted
separator directly.

The simulator-adapter/Xyce migration caught an important bug in that transfer harness:
the diagnostic had been instantiating local \(\mathrm{scorep}/\mathrm{scoren}\)
capacitors on top of the production \code{temporary\_caps} definitions.  Xyce
rejected the duplicate devices; ngspice had been permissive enough that the
old diagnostic could still run.  The harness now uses only the production
score-cap/reset cells, and unit tests assert that the rendered ngspice and Xyce
circuit bodies are identical and contain each split score capacitor once.
After this fix, the conclusion is unchanged but cleaner: with the 3-class
\code{mnist3fixed8\_30} separator, the gate-stack split-score readout reaches
63.3\% score accuracy at scale 5 and 10, and a rectified capacitor
parameterization reaches 66.7\% in the transfer-only harness.
Sweeps over early sample time, \(0.02\times\)--\(0.1\times\) branch width,
readout center voltage, and pass-activation topologies do not recover the
100\% ideal separator.  The transfer harness now reports two explicit
calibration controls: a diagonal per-class gain/offset fit from measured
scores back to the ideal logits, and a full affine class mixer.  On
\code{device\_readout\_transfer\_v689\_prog\_rect\_scale002\_affine}, raw
split-score accuracy is 66.7\%, the diagonal oracle fit reaches only 60.0\%,
and even the full affine oracle reaches only 73.3\% on the same 30 examples.
This points away from a mere timing, common-mode, or row-bias issue; the
readout transfer itself is warping or losing enough hidden-feature information
that ideal linear weights are not a good programmed state for this topology.

We then tested whether the problem is only the software-weight-to-capacitor
mapping.  The new \code{run\_device\_readout\_capfit.py} diagnostic first
measures the single-branch MOS basis
\(E_{\mathrm{MOS}}(V_{\mathrm{act}},V_{\mathrm{cap}})\), then greedily chooses
the actual stored capacitor voltages to classify the held activations under
that measured branch basis.  In the full-width gate-stack setting,
\code{device\_readout\_capfit\_v690\_gate\_fullwidth} reaches 90.0\%
accuracy in the additive branch surrogate, but programming those same cap
voltages into the real transfer deck,
\code{device\_readout\_transfer\_v691\_capfit\_fullwidth}, gives only 56.7\%
raw split-score accuracy.  The same test in the nominal small-signal region is
also negative: \code{v692} reaches 86.7\% in the surrogate, while
\code{v693} gives 33.3\% in SPICE; constraining the caps to
\(0.16\)--\(0.56\,\mathrm{V}\) gives \code{v694}=86.7\% surrogate but
\code{v695}=33.3\% actual.  A buffered pass-activation topology repeats the
pattern: \code{v696}=86.7\% surrogate and \code{v697}=33.3\% actual.  This is
stronger evidence than the programmed-separator controls: even cap voltages
chosen for a measured hardware branch basis do not survive simultaneous
multi-branch readout.  The missing primitive is therefore not just a better cap
initializer; the readout topology needs either local current summing that is
additive under fan-in, or an explicit class-coupled normalization/competition
stage before score storage and error generation.

The first local-current-summing check is encouraging.  A new transfer topology,
\code{split\_score\_clamped\_current}, replaces each floating
\(\mathrm{scorep}/\mathrm{scoren}\) capacitor with a low-impedance voltage
clamp and measures the branch current absorbed by that node.  This is a
diagnostic virtual summing node, not yet a final transistor-only score circuit,
but it directly tests whether floating score-cap interaction is the readout
failure.  With the old rectified programmed separator it still reaches only
66.7\%, so the ideal linear weight mapping remains poor.  But with capacitor
voltages fitted for the hardware branch basis, the low-impedance current node
recovers much of the lost information: the full-width cap program from
\code{v690} gives \code{device\_readout\_transfer\_v699\_clamped\_capfit\_fullwidth}
=83.3\%, compared with 56.7\% for the same caps on floating score capacitors.
Fitting directly against a clamped-current branch surface gives matching
surrogate and transfer behavior: \code{v700} predicts 83.3\%, and
\code{v701} measures 83.3\% in the transfer deck at a \(0.2\,\mathrm{V}\)
clamp.  Sweeping the clamp operating point then finds the first 90\% 3-class
readout-expression result: \code{device\_readout\_transfer\_v704\_clamp0p0}
and \code{device\_readout\_transfer\_v704\_clamp0p1} both reach 90.0\%
actual SPICE score accuracy on the 30 held examples.  This does not finish the
MNIST learner, but it identifies the next concrete circuit direction: replace
floating score-cap accumulation with a transistor-level current-summing or
current-mirror stage that keeps the summing node low impedance, then generate
the class decision and error rails from those currents.

The next transistor-level approximation replaces the ideal clamp with a
diode-connected \(\mathrm{NSENSE}\) load at each score node.  Reading the diode
node voltage helps but does not fully preserve the current-mode result:
\code{device\_readout\_transfer\_v706\_diode\_w512} and
\code{v706\_diode\_w1024} reach 83.3\% after fitting against the corresponding
diode-voltage branch surface.  The more relevant current-mirror interpretation
is to use the diode-connected device as the input leg of a mirror and score by
its drain current rather than by its compressed gate voltage.  The
\code{split\_score\_diode\_current} diagnostic measures that diode current via
a zero-volt sense source while leaving the score node transistor-clamped.  This
recovers the 90\% direction without ideal voltage-source clamping:
\code{device\_readout\_transfer\_v708\_diodecur\_w1024},
\code{v708\_diodecur\_w2048}, and \code{v708\_diodecur\_w4096} all reach
90.0\% actual SPICE score accuracy on the same held 3-class case.  The design
lesson is now sharper: the next production readout should not consume the score
node voltage directly.  It should make \(\mathrm{scorep}/\mathrm{scoren}\)
low-impedance diode/mirror input nodes, copy their currents into a class
competition/error generator, and only store voltages where state must persist.

The first production bridge for that idea is now available as
\code{--output-head split\_score\_diode\_diffpair}.  It leaves the readout
matrix wiring unchanged, diode-loads each \(\mathrm{scorep}_k\) and
\(\mathrm{scoren}_k\) node with matched \(\mathrm{NSENSE}\) devices, and then
uses a local source-coupled output pair from the diode-loaded score voltages.
This is not as clean as measuring the diode current with a simulator sense
source, but it is a transistor-only proxy for a mirrored-current input stage
that can live inside the full training deck.  The first default smoke was a
negative result: with a \(10\,\mathrm{fF}\) output cap and a \(0.3\,\mathrm{ns}\)
window, distinct score cases over-discharge to the same active-low output.
The small output-head transfer sweep found a usable unsaturated regime:
\code{device\_output\_head\_transfer\_diode\_dpair\_cap100\_t020}, using
\(100\,\mathrm{fF}\) output caps, \(1024\,\mu\mathrm{m}\) diode loads, and a
\(0.2\,\mathrm{ns}\) window, preserves every non-tie 3-class signed-score
argmax.  A full-generator smoke,
\code{device\_xor2\_diode\_dpair\_smoke}, confirms the new head can be
instantiated in the production train/eval deck with adapter-rendered ngspice
netlists.  It is only an eval-only wiring smoke, not a learning result.

A single-branch characterization harness,
\code{run\_device\_readout\_branch\_surface.py}, now measures the actual
readout MOS kernel
\[
  \Delta V_{\mathrm{score}}
  =
  E_{\mathrm{MOS}}(V_{\mathrm{act}},V_{\mathrm{weight}})
\]
for the production gate-stack and pass-activation branches.  The compact
ngspice sweep is reassuring in one respect: both positive and negative branches
are monotone in activation and weight voltage, and the two branch polarities
match.  The harness now uses the same spicelib-backed deck rendering path as
the full learner, so ngspice/Xyce differences are not caused by duplicate
generation code.  But the branch is not a linear multiplier in the usual operating
range.  With the default \(10\,\mathrm{fF}\) score cap and full readout width,
the gate-stack branch already moves the score cap by about
\(170\,\mathrm{mV}\) at \(V_{\mathrm{act}}=0.3\,\mathrm{V}\) and
\(V_{\mathrm{weight}}=0.3\,\mathrm{V}\), and it largely clips by
\(V_{\mathrm{weight}}\approx0.64\,\mathrm{V}\).  A bilinear fit on the compact
surface gives only \(R^2\approx0.93\) for gate-stack and \(R^2\approx0.916\)
for pass-activation.  Moving the storage center down into the apparent
transition region does not solve the 3-class transfer check: center
\(0.16\,\mathrm{V}\), scale 1 gives 36.7\%, and rectified scale 5 gives 40.0\%.

The more useful primitive result is small-signal: with a \(100\,\mathrm{fF}\)
score cap, \(0.02\times\) readout width, and early sampling at \(0.9\,\mathrm{ns}\),
the same gate-stack branch has a much better bilinear fit
\((R^2\approx0.965)\), and its score movement remains below
\(180\,\mathrm{mV}\) on the measured grid.  Exposing \code{--score-cap-f} in
the generator makes this knob testable in the full circuit.  The first
transfer-only check at \(0.02\times\), \(100\,\mathrm{fF}\), and early sampling
does not classify correctly by raw argmax, but the per-row score correlations
with the ideal separator are high (\(0.62,0.87,0.77\)); a posthoc row-affine
calibration reaches 66.7\% and a full linear calibration reaches 73.3\%.  So
the next circuit step should not just tune the branch center.  It should add a
hardware-native row normalization/current competition or a differential
score-comparison stage that removes row offsets and common-mode score movement
before the class decision and before the error rails.
Evaluating the tuned differential-pair current competition on measured
split-score traces confirms the distinction.  On the default scale-5 transfer
trace it gives the same 63.3\% class accuracy as the raw split-score argmax; on
the \(0.02\times\), \(100\,\mathrm{fF}\), early-sampled trace it still collapses
to class 1.  So the differential pair is useful as an output/error primitive,
but it cannot recover information that the preceding readout transfer has
already collapsed into row offsets.

The same split-score storage has now been moved into the full device generator
as \code{--output-head split\_score\_caps}.  In this mode each class has
physical \(\mathrm{scorep}_k\) and \(\mathrm{scoren}_k\) capacitors, and the
ordinary \(\mathrm{out}_k\) capacitor is driven by a transistor differential
head.  Programmed-separator controls confirm the diagnosis rather than solving
the problem: with the 3-class \code{mnist3fixed8\_30} separator, the internal
\(\mathrm{scorep}-\mathrm{scoren}\) argmax reaches 66.7\% at scales 5 and 10,
but the physical \(\mathrm{out}\) argmax reaches only 60.0--63.3\%.  Resetting
\(\mathrm{out}\) to the same common-mode rail as the split score capacitors and
trying \(0.30\ \mathrm{V}\) and \(0.50\ \mathrm{V}\) common modes does not
change this.  The next output primitive should therefore compare split-score
currents directly, or generate the error rails from the split score caps,
rather than forcing the evidence through the present single output capacitor.
The matching zero-epoch production controls now give 60.0\% final output
accuracy for symmetric \code{csv\_readout} programming and 63.3\% for
\code{csv\_readout\_rectified}, with score argmax still at 63.3\%.  Rectified
programming is therefore a small improvement, not a solution.
The full training analogue also fails in the same way: the
\code{device\_mnist3fixed8\_30\_v642\_scorecap100\_w002\_ng} run uses
\(0.02\times\) forward readout devices, \(100\,\mathrm{fF}\) score caps, the
reversed one-hot write polarity, and the previous target/non-target gate-width
mobility fix.  Its initial evaluation is 50.0\%, but after two epochs final
output and score accuracy both collapse to 33.3\%, predicting class 1 for all
samples.  The readout rows show large common-mode branch motion
(\(\approx -2.9\,\mathrm{V}\) summed over positive/negative branches) while the
signed row deltas remain much smaller.  This is the current multiclass blocker:
the learning loop needs an output/error primitive that trains on differential
score evidence and rejects row-common movement during the write decision.

We also tested the first such error-rail variant,
\code{ce\_split\_score}.  This keeps the split score storage and generates the
target/non-target write rails from \(\mathrm{scorep}_k\), so the error circuit
does not depend on the final \(\mathrm{out}_k\) capacitor.  With the earlier
bounded write rails \((V_{\mathrm{high}},V_{\mathrm{low}})
=(0.58,0.16)\ \mathrm{V}\), all three output rows moved in the negative signed
direction and the 3-class run collapsed to 33.3\% final accuracy.  This exposed
a simpler parameter bug: the nominal ``charge'' rail was below the usual random
readout center of \(0.64\ \mathrm{V}\), so the positive write path had little
or no upward headroom.  The necessary screen is therefore:
\[
  V_{\mathrm{low}} < \theta_{\mathrm{init}} < V_{\mathrm{high}}
\]
but this is not sufficient.

A new readout-write-selectivity harness now bypasses the output and error
circuits and drives the production \code{direct\_flow.readout\_flow\_updates}
fragment with explicit one-hot \(\mathrm{dp}/\mathrm{dn}\) rails.  With
\(V_{\mathrm{high}}=1.00\ \mathrm{V}\), \(V_{\mathrm{low}}=0.16\ \mathrm{V}\),
initial readout state \(0.64\ \mathrm{V}\), and hidden activations
\((0.8,0.45)\), the normal multiclass polarity moves the target row down by
about \(4.845\,\mathrm{mV}\) and each non-target row up by the same amount.
The reversed polarity gives the desired one-vs-rest motion: target row
\(+4.845\,\mathrm{mV}\), non-target rows \(-4.845\,\mathrm{mV}\).  This means
the older binary reversed-polarity control does not transfer directly to the
explicit multiclass one-hot rail convention.

A composed readout/error/write harness now inserts the production
\code{output\_forward}, \code{error\_cells}, and
\code{readout\_flow\_updates} fragments in one transient while holding hidden
activations externally.  This catches wiring mistakes that the isolated
\(\mathrm{dp}/\mathrm{dn}\) harness cannot see.  The first composed run exposed
one such bug: the output-bias write cell has no pre-activation gate, so its
charge/discharge branch orientation is opposite to the row synapse cell.  The
row caps moved target-positive and non-target-negative under reversed polarity,
but the bias caps moved the other way.  Swapping only the bias write rails fixes
the composed primitive: both ngspice and Xyce now report target-positive row and
bias deltas and non-target-negative row and bias deltas for all three labels,
with key deltas matching to roughly \(10^{-5}\,\mathrm{V}\).

Using the locally correct reversed polarity in the full 3-class circuit still
does not solve learning.  High-rail \code{onehot}, \code{ce\_out}, and
\code{ce\_split\_score} runs all collapse to 33.3\%; target-heavy one-hot
rails also collapse, and a smaller readout step only reaches 36.7\%.  The
post-fix 3-class readout-only control is more informative: ngspice and Xyce
agree closely, but all three readout rows still drift negative over the
balanced dataset and final accuracy falls to chance.  So the present blocker is
not simulator disagreement alone.  It is an aggregate one-vs-rest mobility and
common-mode problem: each class is a target once but a non-target twice in a
3-class balanced stream, so the target write must be much stronger than a
single non-target write, and the differential output/error head must avoid
turning common-mode drift into class evidence.  A first attempt to increase the
one-hot target width does not actually change the mobility enough: composed
Xyce runs at \(128/64\), \(192/64\), and \(192/32\,\mu\mathrm{m}\) target/
non-target error widths still produce target row deltas near \(+6.8\) to
\(+7.0\,\mathrm{mV}\) and non-target row deltas near \(-7.2\) to
\(-7.3\,\mathrm{mV}\).  A matched ngspice \(192/32\,\mu\mathrm{m}\) control
agrees.  The error rails are already near \(1.04\,\mathrm{V}\), so changing
these device widths mostly saturates the same rail voltages instead of giving a
usable target/non-target mobility ratio.

The more useful knob is at the write stack itself.  The generator now exposes
optional final error-gate widths for the \(\mathrm{dp}\) and \(\mathrm{dn}\)
write rails.  This is different from changing the stored-weight branch widths:
it changes the transistor that locally admits target or non-target error into
the update stack.  In the composed reversed-polarity one-hot harness, setting
\[
  W_{\mathrm{dp\ gate}}=0.00012\,\mu\mathrm{m},
  \qquad
  W_{\mathrm{dn\ gate}}=0.000002\,\mu\mathrm{m}
\]
with output-bias writes disabled gives the first useful 3-class mobility
balance: target row deltas are about \(+8.6\,\mathrm{mV}\), while non-target
row deltas are about \(-2.0\,\mathrm{mV}\).  That is large enough that one
target exposure can dominate the two non-target exposures in a balanced
3-class stream.  In the full 30-sample 3-class gate this still does not solve
classification: with output-bias writes disabled, the row totals no longer all
drift negative, but the physical output still tends to collapse to class 1.
The newer split-score CE gate improves the internal differential score rails
rather than the final output head: \code{device\_mnist3fixed8\_30\_v643}
and the adapter-rendered \code{v644} split-score-diffgate output-head smoke
both finish at 33.3\% physical-output accuracy, while the final
\(\mathrm{scorep}-\mathrm{scoren}\) argmax reaches 56.7\%.  Follow-up
adapter-rendered \code{v645}--\code{v649} output-head checks keep the same
separation: charge-gated and active-low differential-pair heads do not yet
rank the physical \(\mathrm{out}\) capacitors the same way as the learned
differential score rails.  The production-output transfer harness
\code{device\_output\_head\_transfer\_v650} makes this smaller and more
diagnostic: with fixed synthetic \(\mathrm{scorep}/\mathrm{scoren}\) inputs,
the existing \(\mathrm{out}\)-voltage heads only match 3--5 of the 7 non-tie
signed-score cases.  The current-competition primitive still matches all
non-tie cases, and the same active-low differential-pair voltage head matches
all non-tie cases once \(\mathrm{Cout}\) is increased from \(20\,\mathrm{fF}\)
to \(100\,\mathrm{fF}\) in the \code{v651} transfer sweep.  This is useful
evidence because it separates the failure: the split score state is learning
some class structure, but the present voltage-mode \(\mathrm{out}\) heads can
saturate before preserving the score ranking.  In the composed 3-class run,
however, \code{v652}--\code{v654} do not recover the physical output:
\(\mathrm{Cout}=100\,\mathrm{fF}\), weak/full output width, and
\(0.30\,\mathrm{V}\) score common-mode variants still finish between 23.3\%
and 33.3\% physical-output accuracy, while the internal
\(\mathrm{scorep}-\mathrm{scoren}\) argmax remains at 56.7\%.  The next
output primitive should therefore expose the current-competition winner or
current share directly to the error rails, or add a true class-coupled sense
stage, instead of relying only on independent \(\mathrm{out}\)-capacitor
discharge.  A first attempt to do this locally,
\code{ce\_split\_dpair}, generates an active-low prediction rail
\(\bar y_k\) from each class's \(\mathrm{scorep}_k/\mathrm{scoren}_k\)
differential pair and drives the target/non-target write rails from that
rail.  The adapter-rendered \code{v655} 3-class smoke simulates cleanly, but
is a negative result: physical output accuracy is 23.3\%, score argmax is
33.3\%, and all three readout rows still drift negative.  So independent local
differential pairs are not enough; the next design needs an explicitly
class-coupled winner/current-share primitive or a separate mobility correction
that prevents the balanced one-vs-rest stream from depressing every row.
The follow-up \code{ce\_split\_compete} primitive adds that class coupling:
each class's \(\bar y_k\) is discharged through a
\(\mathrm{scorep}_k/\mathrm{scoren}_k\) branch that shares one tail node
(\(\mathrm{ccsrc}\)) across classes.  This changes the failure mode but still
does not solve the learner.  The default \code{v656} run finishes at 20.0\%
physical accuracy and 33.3\% score accuracy, with all three readout rows now
moving positive instead of negative
\((+0.129,+0.236,+0.029)\,\mathrm{V}\).  A stronger-target/weaker-non-target
\code{v657} variant reaches the same accuracies and pushes the rows even more
positive \((+0.187,+0.358,+0.089)\,\mathrm{V}\).  The conclusion is narrower:
the shared-tail error block can change aggregate mobility sign, but it is not
yet producing class-selective enough write rails.  The next primitive should
measure or store a true winner/current-share rail and use that directly in the
write stack, rather than only thresholding a discharged \(\bar y_k\) capacitor.

Two direct-current variants make the failure more specific.  The
\code{ce\_split\_current} rule removes the thresholded \(\bar y_k\) conversion
from the non-target side and feeds \(\mathrm{dn}_k\) from a shared score-current
source \(\mathrm{cesrc}\).  The composed readout/error/write diagnostic gives
the right per-sample signs, but the full \code{v658} run still finishes at
20.0\% physical accuracy and 33.3\% score accuracy, with all three readout rows
positive \((+0.338,+0.380,+0.259)\,\mathrm{V}\).  Increasing the non-target
write gate in \code{v659} reduces the row drift but does not change the
qualitative result: all rows remain positive
\((+0.260,+0.320,+0.171)\,\mathrm{V}\).  The \code{ce\_split\_hybrid} rule
then combines shared-tail \(\bar y_k\) target suppression with the direct
non-target current source.  It again improves the aggregate row balance but
does not solve the learner: \code{v660} remains at 20.0\% physical and 33.3\%
score accuracy, with row drift
\((+0.215,+0.285,+0.120)\,\mathrm{V}\).  The practical diagnosis is that the
target-side \(\mathrm{vdd}\!\rightarrow t_k\!\rightarrow\mathrm{dp}_k\) stack is
still saturating; changing device widths mostly changes write mobility after a
nearly full-swing target error has already been created.

The next primitive, \code{ce\_split\_limited}, changes that physical source
rather than only the write gate.  Target \(\mathrm{dp}_k\) is now fed from a
current-starved source rail \(\mathrm{ctsrc}\), while non-target
\(\mathrm{dn}_k\) remains fed from \(\mathrm{cesrc}\).  In the composed
3-class diagnostic, this makes target-error magnitude controllable: with
\(\code{residual\_target\_width\_u}=0.02\), target row movement is only about
\(+0.0008\,\mathrm{V}\), while non-target rows remain around
\(-0.0025\) to \(-0.0030\,\mathrm{V}\); with
\(\code{residual\_target\_width\_u}=0.1\), target movement rises to about
\(+0.0057\,\mathrm{V}\), close to the expected 3-class one-target/two-non-target
balance.  This is the first split-score CE-like error block where the target
rail is not automatically full-swing.  Full 30-sample \code{mnist3fixed8\_30}
runs confirm that this is a real mobility improvement but not yet a learning
solution.  With \(\code{residual\_target\_width\_u}=0.1\), \code{v661} changes
the aggregate row drift from all-positive to two positive rows and one nearly
flat row \((+0.085,+0.170,-0.001)\,\mathrm{V}\), but accuracy remains 20.0\%
physical and 33.3\% by score.  With
\(\code{residual\_target\_width\_u}=0.06\), \code{v662} crosses the balance
point: two rows move negative and one positive
\((-0.023,+0.087,-0.101)\,\mathrm{V}\), and physical accuracy nudges from
20.0\% to 23.3\%, but the score argmax still collapses to class 1.  Enabling a
small output-bias write in \code{v663} breaks that score collapse
(final score histogram \(3/9/18\) instead of \(0/30/0\)) and improves physical
accuracy to 26.7\%, but it is still far below what the measured hidden
activations can support.

A programmed-separator control makes that last point explicit.  A software
multiclass perceptron fitted to the measured initial hidden activations has
100\% ideal accuracy on the same 30 examples, but mapping it into the
capacitor readout with \code{csv\_readout\_rectified} and the split-score
diffpair head gives only 63.3\% in the full \code{v664} zero-training SPICE
eval at scale \(10^{-3}\).  A faster readout-transfer sweep peaks at 66.7\%
for rectified scales \(2\times10^{-3}\) and \(4\times10^{-3}\); larger scales
saturate and fall back toward chance, while the differential
\code{csv\_readout} mapping is no better.  So the immediate blocker is now
more precise: before a learned CE-like update can reach the separable solution,
the signed readout cell and split-score output head must express a known
multiclass separator with much higher fidelity.

The next useful experiments are therefore: keep the default-rail
bounded-discharge readout anchor
\[
  \code{source\_follower}
  + \code{out\_senseamp}
  + \code{target\_mistake},
\]
use checkpoint runs to tune the stop time, keep hidden-delta cap/leak damping
enabled for full-hidden runs, and characterize row-wise one-vs-rest write
mobility before scaling the ten-class readout.  The true weighted hidden layer
should still be brought up separately with a simpler readout interface before
recombining it with the full training loop.

\section{Phase Timing}

The present direct-flow timing template is not a digital clock in the usual
logic sense; it is a sequence of analog guide windows.  A typical cycle is:
\begin{center}
\begin{tabular}{ll}
\toprule
Window & Phase \\
\midrule
0.00--0.50\,ns   & reset temporary state \\
0.75--3.00\,ns   & forward settling and trace capture \\
3.25--4.40\,ns   & output compare \\
5.25--6.50\,ns   & error-node formation \\
6.75--11.20\,ns  & backward/write flow \\
9.25--11.20\,ns  & optional latched apply sub-window \\
\bottomrule
\end{tabular}
\end{center}
The long-term self-timed version would replace some of these fixed Python
windows with circuit-derived events, for example a sense-amp decision or output
spike arrival opening the backward/write path.
