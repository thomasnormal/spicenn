# Engineering Log

## 2026-05-21

- Verified local SPICE tools for this workspace: `ngspice` is installed at `/usr/bin/ngspice` and reports version 42; `Xyce` is installed at `/usr/local/bin/Xyce` and reports 7.10.0.
- Focused SPICENN tests initially could not collect because declared Python dependencies were missing (`scipy`, `PySpice`, then CPU-only `torch`/`torchvision` for MNIST dataset loading). Installed those in the user site packages. Aborted the default CUDA `torch` wheel path and purged the pip cache before installing CPU-only wheels.
- The tiny MNIST dataset files are not present under this repo's `data/` path. The loader deliberately uses `download=False`, so MNIST smokes need either a local dataset cache or an explicit dataset-download policy change.
- Reproduced the readout eligibility bottleneck on built-in SPICE smokes: nonzero ReLU activations around 0.06-0.23 V can be useful, but a 0.3 V spike reference leaves readout pretrace gates mostly off, so target errors only update bias or analog fallback paths. A lower reference exposes real hidden eligibility coverage and improves the `sum_extremes` smoke.
- Downloaded MNIST through the existing high-level `load_mnist_sequence` path. The shared `spice/datasets.py` path was the inconsistent one: it hard-coded `download=False`, which blocked sparse/device MNIST smokes on a fresh checkout. Added an explicit download flag instead of silently changing default network behavior.
- After the dataset path was unblocked, `run_device_spicenn_sparse_forward.py --dataset mnist3fixed8_3 --download-dataset ...` completed electrically with full pretrace coverage, but final sparse-device evaluation was still only 1/3. The immediate blocker moved from dataset plumbing back to architecture/training quality.
- Tried to reproduce a current all-SPICE local-feature batch-op baseline. The first moderate run failed before accuracy because `run_spice_mnist_local_feature_batch_op_train.py` wrote `wrdata` into `spice/results/` without creating that directory. Added output-directory creation and verified a 200-train/100-test smoke completes. That runner is the current practical path for reproducing the historical >90% local-feature MNIST results.
- Re-running the full SPICE goal audit on this checkout exposed an artifact-location fragility: the script only scanned `spice/results/`, while this repo stores many result tables under `results/tables/`. Added a resolver and regression tests for `spice/results`/`results/tables` summary fallback. The old high-evidence audit snapshot still depends on historical summary JSONs that are not present in this checkout, so generated audit outputs must not be treated as new evidence unless the artifacts are regenerated or restored.
- The full test suite had three stale/adjacent failures after the SPICENN/pretrace changes. Two tests still expected the synapse-spike comparator path to use `NREL`, but `PreTraceCell` now correctly uses the low-threshold `NSENSE` sense device. The third failure was a real positional-argument drift in the readout-array `flow_offstate` load path; converting that call to keyword arguments fixed the circuit option mapping and restored the suite.
- A current 5,000-train / 2,000-test `run_spice_mnist_local_feature_batch_op_train.py` reproduction attempt with `10x10 b4 stride2 c2`, 5 epochs, batch size 100, and lr 0.03 was too large for an interactive slice: after about four minutes it was still driving a per-step ngspice deck. Stopped it and removed the generated `codex_current_smallnet10_b4_s2_c2_5k2k_e5_lr003` step artifacts. This runner needs either a smaller smoke, a resumed existing checkpoint, or a longer unattended run to regenerate the historical >90% evidence.
- Added chunking/checkpoint support to the batch-op local-feature runner: `--max-train-batches` caps each invocation after the deterministic epoch offset/sample slice, and `--checkpoint-every-batches` writes an init-compatible `*_latest_weights.npz` plus progress JSON during training. A tiny ngspice smoke trained one batch, resumed from the latest checkpoint at `--epoch-train-offset 2`, and produced the expected checkpoint metadata; generated smoke artifacts were removed.
- Ran the new chunking path on the actual high-margin `10x10 b4 stride2 c2` local-feature topology. A first 10-sample ngspice batch plus 100-image eval completed in 6.9 s and wrote `codex_smallnet10_b4_s2_c2_slice0_b10_latest_weights.npz`; a resumed slice from `--epoch-train-offset 10` trained two more 10-sample batches in 9.0 s and wrote `codex_smallnet10_b4_s2_c2_slice10_b10x2_latest_weights.npz`. Accuracy is still near random this early (7-8% on 100 eval samples), but the all-SPICE target branch can now advance in resumable chunks. Generated `.cir` decks were removed; small checkpoint/result artifacts remain under `spice/results/` for continuation.
- Added `--skip-heldout-eval` to the same runner so expensive resumable chunks can train and checkpoint without paying for a held-out SPICE eval every invocation. A tiny ngspice train-only smoke produced `null` held-out metrics and an init-compatible latest checkpoint, and the full test suite passed afterward.
- Regenerated a current high-margin `10x10 b4 stride2 c2` local-feature checkpoint with fast PyTorch training on 5,000 MNIST train / 1,000 held-out samples. It crossed 90% at epoch 4 and ended at 92.7% after 10 epochs. ngspice operating-point eval of the exported best checkpoint with `--linear-output` matched the same 92.7% on the 1,000-image held-out slice. This is SPICE forward evidence for the compact topology, not all-SPICE training; the all-SPICE random-init trajectory is still only at 11-12% after 630 seen samples.
- Re-evaluated the same exported compact checkpoint on a broader 2,000-image held-out MNIST slice in ngspice. The SPICE operating-point deck reached 91.7% (`1834/2000`) with `--linear-output`, so the current compact topology has reproducible >90% SPICE forward evidence beyond the original 1,000-image slice. The generated 2.5 MB eval deck was removed; summary/curve CSV were copied to `results/tables/`.
- Fast reference evaluation of the same compact checkpoint on the full 10,000-image MNIST test set reached 91.8% (`9180/10000`). A full ngspice operating-point eval over all 10,000 test images also reached 91.8% with `--linear-output`, taking about 30 minutes with 200-image eval decks. This is now full-test SPICE forward evidence for the 5k-trained compact checkpoint; it still does not close the end-to-end all-SPICE training gap.
- Started phase-transient SPICE training continuation from the full-test >90 compact checkpoint. A short `lr=0.003` continuation stayed above target for 4 real SPICE-trained samples on the 1,000-image ngspice slice (`92.9%` final, `93.4%` best after the first chunk), but extending the same update scale to 20 samples degraded to `87.2%`. Reducing phase update scale to `lr=0.0003` kept the 20-sample SPICE-trained continuation stable at `91.8%` on the same 1,000-image ngspice eval. This makes phase update scale the next concrete stability knob for longer all-SPICE continuation.
