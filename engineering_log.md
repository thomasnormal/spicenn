# Engineering Log

## 2026-05-22

- Replaced the legacy Python netlist-normalization dependency with a neutral, spicelib-backed SPICE adapter. The adapter now keeps raw generated circuit bodies textual, owns title/end/control-block rendering, strips ngspice-only control blocks for Xyce, and uses spicelib for simulator executable resolution while preserving SPICENN's output contract (`ngspice -b deck`, `Xyce deck`). A first attempt to use spicelib's raw/log runner directly exposed two incompatible defaults: ngspice rejects top-level `.measure` when `-r` rawfile output is forced, and Xyce `.print` readers stop seeing `.prn` files when `-r` is forced.
- Added in-transient prefix probes to the fully on-device local-feature phase runner. The probes are `.measure` diagnostics inside the same uninterrupted transient, then compared against the post-run batch-op reference per prefix. A 4x4 b2 stride2 c1 Xyce smoke stayed aligned through 10 updates (`cos=0.9999577`, sign alignment `98.57%`). An 8x8 b4 stride2 c2, channel-2 diagnostic showed gradual accumulated drift rather than an immediate wiring error: cosine was `0.99996` at update 4, `0.99978` at 8, `0.99898` at 16, `0.99785` at 32, and `0.99356` at 50. A first 10x10 b4 stride2 c2, channel-2 smoke completed in the target topology but already missed the strict direction gate at 10 updates (`cos=0.99834`, sign alignment `98.97%`), so the next correction should target accumulated analog integration/drift before longer 10x10 learning runs.
- Fixed the accumulated drift source: finite-edge phase clocks have trapezoid area `phase + edge`, while the gradient/apply integrators had been normalizing by `phase`. Normalizing update integrators by `TAREA=phase+edge` restored the continuous-vs-batch-op contract on the target topology: the 10x10 b4 stride2 c2, channel-2, 10-update Xyce smoke improved from `cos=0.99834`, sign alignment `98.97%`, max state error `3.3e-2` to `cos=0.9999999991`, sign alignment `100%`, max state error `3.5e-5`. The 8x8 b4 stride2 c2, channel-2, 50-update smoke similarly improved to `cos=0.9999999964`, sign alignment `100%`, max state error `1.23e-4`.
- Exposed local activation variants in the continuous phase runner so neuron forward/backward choices can be compared under the same fully on-device contract. A 4x4 10-update Xyce screen passed for `tanh`, `relu`, `clipped-relu`, and `diff-clipped-relu`. On the 10x10 b4 stride2 c2 target topology at 5 updates, `tanh` and `diff-clipped-relu` passed with 100% sign alignment, while single-ended `relu`/`clipped-relu` had excellent cosine but only `92.78%` sign alignment. This makes differential/clipped activation handling the stronger next branch for larger robustness/learning experiments.
- Added a phase-variant sweep harness so activation/neuron choices can be run as a reproducible matrix while preserving the underlying runner's `batch_size=1`, one-transient training contract. A compact 10x10 b4 stride2 c2, channel-2, 8-update Xyce sweep over `tanh` and `diff-clipped-relu` clips `0.5/1.0` kept all variants electrically aligned (`cos >= 0.999999998`, sign alignment `100%`, max state error about `2.4e-5`). Accuracy stayed flat at 12% on a 50-image eval after only 8 online samples, so this was a robustness/contract screen rather than a learning result. The harness is now the right place to add broader synapse/neuron forward/backward variants before committing to long 10x10 learning runs.
- Ran the first corrected medium-scale fully on-device target-topology learning probe: 10x10 b4 stride2 c2, channel-2, `diff-clipped-relu`, `batch_size=1`, 50 online updates, Xyce one-transient training, 200-image eval. The run preserved the contract (`continuous_transient_contract_met=true`, direction cosine `0.9999956`, sign alignment `100%`, final eval matched the batch-op reference exactly) and crossed the nontrivial-learning gate: initial eval `12%`, final eval `20%`, improvement `+8%`. This is still far from the >90% objective and only 50 online samples, but it is meaningful learning on the target topology without Python weight checkpointing between samples. Summary/equivalence/probe CSVs were copied to `results/tables/`; generated decks and weight checkpoints were removed.
- Added explicit neuron/backward/synapse variant knobs to the local-feature phase path and its matched batch-op reference: leaky ReLU and softplus forward activations, exact/stored-gate/floor-exact derivative masks, and full/clipped readout-feedback transfer for backward hidden deltas. A 36-row Xyce robustness screen on the target 10x10 b4 stride2 c2, channel-2 topology showed a clear analog-ReLU split: `tanh`, `diff-clipped-relu`, `leaky-relu`, and `softplus` all preserved the fully-on-device contract with 100% sign alignment, while plain single-ended ReLU failed all six rows despite high cosine (`~92.5-97.7%` sign alignment). Softplus had the smallest short-screen state error, but the 50-update learning probe only moved `14% -> 16%`; leaky ReLU with 1% negative slope and clipped backward readout-feedback moved `6.5% -> 32%` on the same 200-image eval while exactly matching the batch-op reference. This makes leaky ReLU the strongest robust analog-ReLU candidate from this slice, with differential clipped ReLU still a good signed bounded alternative.
- Extended the leaky-ReLU/clipped-feedback branch to a 100-sample uninterrupted Xyce transient on the target topology (`batch_size=1`, `10x10 b4 stride2 c2`, channel-2, `lr=0.8`). The run again preserved the fully on-device contract (`continuous_transient_contract_met=true`, direction cosine `0.999999991`, sign alignment `100%`, final eval matched the batch-op reference exactly) and stayed clearly above random, moving a 300-image eval from `8%` to `31%`. Because this is essentially flat versus the 50-update leaky result (`32%` on 200 images), the next high-yield branch is not merely longer `lr=0.8` training; it should test update scale and backward feedback transfer (`readout` vs clipped/sign) on leaky ReLU, or combine leaky forward transport with the differential clipped bounded representation.
- Tested two direct leaky-ReLU branch hypotheses on the target topology. Full readout feedback at the same `lr=0.8`, 50-update, 200-eval setup passed the contract but reached only `22%`, below clipped feedback's `32%`, so the feedback clip is not the immediate learning bottleneck. Doubling clipped-feedback learning rate to `lr=1.6` also passed the contract but dropped to `12.5%`, so the plateau is not fixed by a larger update scale. Added `--eval-probe-updates` diagnostics to evaluate measured in-transient probe states after the uninterrupted transient finishes; a small Xyce smoke confirmed probe CSVs now carry phase/reference eval accuracy without Python checkpointing during training. The next target run should use this to locate the update horizon where leaky/clipped peaks before trying longer or scheduled runs.
- Found a comparability bug in `load_mnist_sequence`: using one RNG stream for both train and held-out sampling made the held-out eval slice depend on `--train-samples`, so 50/64/100-update phase runs were not measuring against the same test subset. Split train/test sampling into independent deterministic streams and added a regression test. Re-running the leaky-ReLU/clipped-feedback probe-eval target branch with stable held-out sampling (`64` online updates, 200 eval images) preserved the contract (`direction cosine 0.999999978`, sign alignment `100%`, eval reference match), but showed weak learning on the fixed slice: initial `9%`, best probe `13.5%` at update 16, final `12.5%` at update 64. This supersedes cross-horizon conclusions drawn only from moving eval slices; future optimization should use stable held-out samples and probably revisit the objective/feature branch rather than simply extending this leaky/clipped setting.
- Re-tested the high-performing batch-op branch's local nonlinearity under the fully on-device phase runner with stable held-out sampling. `tanh` + full readout feedback on the target topology (`64` online updates, 200 eval images, `lr=0.8`) learned better than leaky ReLU: initial `11%`, probes `13.5%` at updates 16/32, final `22%`. Direction still matched the batch-op reference well (`cos=0.9999589`, sign alignment `100%`), but the strict full contract failed because final phase/reference eval differed by one sample (`22.0%` vs `21.5%`) and state error jumped at update 64 (`state_max_abs_diff=0.028`). Reducing the store aggressiveness from `settle_ratio=80` to `20` did not fix the drift (`state_max_abs_diff=0.031`, same eval mismatch). The next branch should keep `tanh` as the learning candidate but target accumulated state drift, likely via timestep/integration strategy or phase scheduling, before attempting longer fully-on-device runs.
- Added effective synapse-transfer variants to the local-feature batch-op and fully on-device phase-transient paths so hidden/readout forward conductance can be swept separately from neuron activation and backward feedback: linear, smooth/tanh-clipped, hard-clipped, and sign/binary transfers. The phase variant sweep now expands hidden/readout synapse modes in addition to activation, derivative, and feedback mode. A tiny non-default Xyce smoke (`tanh`, hidden `tanh-clipped`, readout `hard-clipped`, `synapse_clip=0.25`, 4x4 b2 stride2 c1, two online samples) preserved the continuous contract (`cos=0.9999999998`, sign alignment `100%`, max state error `1.18e-5`). An 8-row target-topology screen (`10x10 b4 stride2 c2`, channel-2, four online samples) crossed `tanh`/`leaky-relu` with linear/tanh-clipped hidden synapses and linear/hard-clipped readout synapses; every row preserved the contract with `100%` sign alignment. Tanh rows had lower short-run state error (`~1.8e-5`) than leaky-ReLU rows (`~4.8e-5` to `5.0e-5`), and tanh-clipping hidden synapses slightly improved both activation families. This screen is still a robustness/equivalence screen, not a learning result, but it gives the next long runs a real synapse axis instead of only comparing neuron nonlinearities.
